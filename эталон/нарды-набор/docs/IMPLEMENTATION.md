# Как собрать экраны

Все координаты ниже относятся к исходнику **941 × 1672 px**. Начало координат — левый верхний угол. Для `sourceRect` используется формат `[left, top, right, bottom]`, правая и нижняя границы не включаются. Размеры в `assets-manifest.json` — размер файла, а не CSS-размер.

## Масштаб и адаптивность

Для сравнения при ширине 390 px коэффициент `390 / 941 = 0,41445`. Например, фишка 60 px отображается примерно 25 px. Не растягивать весь экран по высоте: применять обычную вёрстку, вертикальный скролл лобби, ограничение ширины контента. Доска всегда сохраняет пропорции `913 / 793`. На низких экранах допустим вертикальный скролл; не сжимать доску независимо по осям.

Верхняя панель «Игры с друзьями» показана на обоих макетах. Проверить оболочку текущего Mini App: если она уже содержит этот заголовок/кнопку назад, не создавать второй экземпляр. Поддержку safe area, доступной высоты Telegram и кнопки возврата согласовать с существующей интеграцией проекта.

## Доска и координаты

В `integration/board-geometry.json` даны 24 пункта, координаты центра первой фишки, направление стопки и проценты. Нумерация: 1–6 снизу справа справа-налево, 7–12 снизу слева справа-налево, 13–18 сверху слева слева-направо, 19–24 сверху справа слева-направо. Это конвенция пакета; сопоставить её с нумерацией движка.

Позиция фишки для пункта `p` и индекса `i` в стопке: `x = p.x`, `y = p.y + i * p.stackDy`. Для стопок более пяти фишек уменьшать интервал так, чтобы стопка помещалась в своей половине, либо использовать числовой счётчик. Подставлять координаты как проценты ширины/высоты контейнера, а не исходного экрана.

Пример: `left = x / 913 * 100%`, `top = y / 793 * 100%`, `width = 60 / 913 * 100%`, `transform: translate(-50%, -50%)`. Не обрезать нижний ряд container padding-ом. Размер светлой фишки 59 × 59 — это реальный срез; для обоих цветов задавать одинаковый визуальный диаметр 60 условных px.

Два кубика примерно в центре правой половины. Их точные рекомендуемые центры записаны в geometry. Визуальную тень добавить CSS; PNG-фишки вырезаны по кругу без внешней падающей тени.

Центральный бар узкий, предназначен как ориентир размещения. Отдельного лотка для снятых фишек в макете нет: использовать существующее отображение проекта или сделать отдельный блок. Не размещать эти фишки на произвольных пунктах.

## Порядок слоёв внутри доски

| z-index | Содержимое |
|---|---|
| 0 | Фон страницы |
| 1 | Пустая доска |
| 2 | Кольца допустимых ходов |
| 4 | Обычные фишки |
| 5 | Кольцо выбранной фишки, кубики |
| 6 | Перемещаемая фишка |
| 20 | Закреплённые панели навигации |
| 100 | Модальные окна |

Декоративные изображения `pointer-events:none`. Для интерактивных фишек — отдельная кнопка/область попадания. Подсветка не перехватывает клики. `zIndex` в manifest — рекомендуемый слой внутри ближайшего блока, а не глобальный уровень приложения.

## Шрифт и внешний вид

По растровому изображению точный шрифт установить нельзя. Близкий старт: `Arial, Helvetica, system-ui, sans-serif`, начертания 400/600/700. На исходнике: название около 78 px, основные кнопки 31–34 px, подписи 25–29 px. Умножать на коэффициент масштаба и затем корректировать оптически. Не опускать обычный текст ниже удобного для телефона размера ради буквального совпадения; для вторичных подписей целиться примерно в 12–14 CSS px.

Базовые цвета и радиусы — в `integration/design-tokens.css`. Это приближённые параметры, подобранные по макетам, а не исходные design tokens автора. SVG-кубики и простые SVG-иконки также воссозданы геометрически. Их происхождение отмечено в manifest.

## Что проверено в пакете

Все PNG открываются, размеры согласованы с manifest; вырезанные иконки и фишки имеют alpha-канал; ссылки на ассеты разрешаются; SVG имеют корректный XML; ZIP проверен по CRC. Визуально проверены пустая доска и обзор нарезки. Интеграция с вашим приложением и игровые правила этим пакетом не проверяются.
