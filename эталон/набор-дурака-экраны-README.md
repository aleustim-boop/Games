# Дурак — 6 экранов, изображения и инструкция по сборке

Пакет нарезан из двух предоставленных изображений 1614×975 px. Здесь шесть отдельных экранов и папки с их компонентами, версии PNG ×2, векторные иконки и инструкции для Claude Code / VS Code. Это дополнение к предыдущему набору экрана самой партии, не замена игровой логики.

## Claude Code: прочитай сначала

1. Прочитай этот файл, `FLOW-AND-STATE.md`, затем README конкретных экранов. Посмотри все шесть `screen.png`.
2. Используй текущий проект и существующий игровой движок. Названия маршрутов в документации описывают назначение экранов; адаптируй их к архитектуре проекта.
3. Скопируй необходимые изображения в локальные assets проекта. Все пути внутри пакета относительные и латиницей.
4. Иллюстрации можно использовать как изображения. Текст, кнопки, фильтры, шаги, значения, аватары и места игроков реализуй компонентами с реальными обработчиками и состоянием.
5. Не накладывай новый текст или новые аватары на растровый блок, который уже содержит их. Полные экраны нужны для сверки, а не как фон работающего приложения.
6. Разные макеты показывают разные партии. Не перезаписывай выбор пользователя примерами «6 игроков», «С ботами», «Подкидной», «2 на 2» при переходе на очередной экран.
7. Не заменяй отсутствующий backend демонстрационными обещаниями. Если нет рейтинга, онлайна или приглашений, сохраняй честный деморежим/недоступное действие.
8. Протестируй сохранение настроек при переходах вперед/назад, оба режима правил, 2–6 игроков, командный режим, онлайн/ботов, фильтры рейтинга и узкие экраны.

## Как устроен архив

| Папка/файл | Для чего |

| `screens/02-rules/` | Шаг 1: подкидной или переводной, пример перевода |

| `screens/06-rating/` | Рейтинг: три фильтра, свое место, лидеры, вкладки |
| `shared/icons/` | 15 SVG-иконок; список назначений в `shared/README.md` |
| `shared/textures/` | Чистый образец красного сукна, исходный размер и ×2 |
| `reference/` | Два неизмененных исходных коллажа |
| `ASSET-MAP.md` | Сводная таблица всех вырезанных компонентов |
| `assets-manifest.json` | Пути, размеры, координаты в коллаже и отдельном экране, назначение |
| `FLOW-AND-STATE.md` | Переходы, сохранение выбора, динамические состояния и ограничения |

В каждой папке экрана:

- `screen.png` — отдельный экран в исходном разрешении.
- `screen@2x.png` — его увеличение в два раза.
- `native/` — компоненты с исходными пикселями.
- `2x/` — соответствующие увеличенные компоненты, суффикс `@2x.png`.
- `README.md` — таблица: имя → координаты → назначение → место и способ применения.

## Что является картинкой, а что нужно сверстать

| Тип в JSON | Содержимое | Применение |
| --- | --- | --- |
| `art` | Карты или кубок, вырезанные из коллажа | Декоративное изображение с исходным фоном. Не прозрачный спрайт |
| `composition` | Составная иллюстрация/стол/баннер с текстом, аватарами или значениями | Статичный блок либо образец для пересборки. Проверить уже нарисованные элементы |
| `ui` | Кнопки, подписи, переключатели, строки рейтинга | Визуальный образец. Для работающего экрана рисовать кодом |

Все PNG прямоугольные и непрозрачные. Скругленные углы, тени, текст и фон сохранены. Перекрытые части не дорисованы. В данном пакете нет пустого овального стола с прозрачными отдельными аватарами. Не используй `seating-table.png` или `room-table.png` как подложку под дополнительные места: на них уже есть люди и подписи.

Главная иллюстрация лобби `hero-with-caption.png` уже содержит слоган. `hero-cards.png` — более короткий фрагмент веера без интерфейсной подписи; нижняя часть предметов немного обрезана. Сохраняй пропорции. Не выдавай эти декоративные карты за комплект для игрового процесса.

## Общий внешний вид и адаптация

- Темный фон, белые крупные заголовки, серый вторичный текст, лаймовые выбранные состояния и основные кнопки. Красное сукно и дерево — только декоративные игровые блоки.
- Ориентировочные цвета: фон `#0B1519`, панель `#111C21`, текст `#F5F6F4`, вторичный `#93A0A9`, граница `#59666E`, акцент `#D0FC67`, сукно `#511017`. Это оценки по изображению, не исходные дизайн-токены.
- Шрифт макета неизвестен. Используй шрифт проекта или системный sans-serif с кириллицей; заголовки и CTA жирные. Слоган лобби имеет засечки и может быть отдельным serif-стилем.
- Отдельные экраны имеют ширину около 520 px и высоту 975 px. Это пиксели исходника, не жесткая ширина сайта. При 390 CSS px коэффициент примерно 0,75; поля 20–27 исходных px соответствуют примерно 15–20 CSS px.
- Фиксируй смысловые отступы, а не координаты всего экрана. Используй flex/grid и нормальную прокрутку. Изображения выводи с сохранением пропорций, без растяжения по одной оси.
- На ширинах 360, 390, 430 px не обрезай названия, CTA и счетчики. Кнопкам и местам игроков обеспечь область касания не менее 44×44 CSS px, даже если рисунок меньше.
- Основное действие в шагах — внизу контента или закреплено с резервом места под него. Нижняя навигация показана только в лобби и рейтинге. Не добавляй ее в мастер и комнату только ради одинаковости.
- Учитывай safe-area и имеющуюся шапку Telegram. Не дублируй уже предоставленные контейнером «назад», название и меню.
- Состояния выбора задавать `aria-checked`/radio или доступными tab/button-компонентами; недоступные действия имеют реальный `disabled`. Иконкам без собственного действия — `aria-hidden`.

## Размеры и качество

Каждый коллаж исходно имеет 1614×975 px, то есть отдельный экран — около 520×975 px. `native` сохраняет исходные пиксели без дополнительной потери качества PNG. `2x` увеличен Lanczos: отдельные экраны примерно 1040×1950 px. Это увеличение не восстанавливает отсутствующие детали и не превращает маленькую вырезку в исходное высокодетальное фото.

Небольшие подписи в оригинале могут выглядеть мягкими; поэтому в приложении их нужно выводить живым текстом. SVG-иконки остаются четкими при масштабировании, но являются заново построенными аналогами, а не извлеченными исходными контурами.

## Машиночитаемая привязка

У каждого экрана и компонента есть идентификатор. В `assets-manifest.json`:

- `sourceId` — исходный коллаж 1 или 2.
- `sourceBox` — `[x,y,width,height]` относительно исходного коллажа.
- `screenBox` — такой же прямоугольник относительно отдельного `screen.png`.
- `path` / `upscaledPath` — обычный и увеличенный файлы.
- `kind` / `usage` — тип и точное назначение.
- `transparent:false` — у растровых фрагментов нет удаленного фона.

Координаты помогают понять расположение и сверить композицию. Они не требуют абсолютного позиционирования всего интерфейса. Имена файлов одинаковы в `native/` и `2x/`, кроме суффикса `@2x`.

## Приемка

После подключения сверить каждый экран со своим `screen.png`, проверить переходы из `FLOW-AND-STATE.md`, отсутствие повторных надписей на картинках и отсутствие устаревших демонстрационных значений в настоящей игре. Профиль и сам экран партии не входят в эти шесть макетов: использовать существующие экраны проекта.
