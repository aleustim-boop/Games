Правила ведения (они же записаны в `CLAUDE.md`):

- **новая просьба записывается сразу**, словами владельца, ещё до раздачи исполнителям;
- **сдали или опубликовали — тоже сразу**, в тот же час;

**Важность — четыре уровня.** «Горит» — игрок видит поломку, берём немедленно.
«Скоро» — владелец ждёт, спросит на днях. «Потом» — нужное, но никто не ждёт.
«Задел» — пригодится, когда вырастем. Уровень ставит штаб, владелец меняет одним словом.

## ЧИТАТЬ ПЕРВЫМ ДЕЛОМ ПОСЛЕ ПЕРЕЗАПУСКА

**1. Поднять службы** — каждую отдельной короткой командой, в фоне:

- сервер комнат: `node server/сервер.js 8790` (порт 8765 занят чужой программой);
- страница игры: `node tests/локальный-сервер.js 8080`;
- бот: `node bot/бот.js`;
- живой дашборд: `node штаб/дашборд.js` (порт 8791) и туннель к нему
  `cloudflared tunnel --url http://127.0.0.1:8791` — новый адрес вписать в шапку;
- туннель игры — `cloudflared`, проверить `tasklist`.

Проверка: `curl -s http://127.0.0.1:8790/` → `{"живой":true,...}`.

**2. Списки ведут программы, а не память штаба.** Расписаний больше нет — они
будили сессию 36 раз в час и жгли лимит владельца впустую. Вместо них две
короткие команды, и звать их надо при каждой постановке и при каждой сдаче:

- `node штаб/в-работе.js` — раздел «В работе», по файлу `штаб/в-работе.json`.
  Время начала программа ставит сама из часов машины;
- `node штаб/списки.js` — очередь, вопросы к владельцу и «Готово», по файлу
  `штаб/списки.json`. Сделанное вычёркивает сама — по следу в коде (появился
  файл, есть строка), а время берёт из записей git.

**Ставя новую задачу в очередь, пиши примету «сделано»** — по какому следу в
коде будет видно, что дело готово. Без неё пункт придётся вычёркивать руками,
и мы вернёмся к тому, с чего начали: очередь висела девятью задачами, пять из
которых давно были у игроков. Формат — в шапке `штаб/сделано.js`.

Отдельно: искать сделанное по словам из заголовков коммитов **не годится** —
проверено на настоящих записях, четыре из пяти находит, а на пятом даёт ложное
срабатывание. Поэтому такой способ только подсказывает «проверьте», но права
вычёркивать не имеет.

**3. Раздать работу заново** по таблице «В работе» ниже: контекст исполнителей
теряется, сделанное остаётся в файлах — каждому сказать «посмотри, что уже лежит
в твоём файле, и продолжи».

**4. Номера версий** смотреть в самом `index.html`, а не здесь: список тут
устаревал быстрее, чем его правили. Одной командой — `grep -o '?v=[0-9]*'
index.html`. Правишь файл — поднимай номер, иначе Telegram неделями показывает
игрокам старое.

**5. Что осталось непроверенным живьём** (нужен глаз человека, не робота):

## Очередь: что увидит игрок

Сверху — то, что берём первым. Только то, что меняет игру для человека.
Раздел переписывает `node штаб/списки.js` по файлу `штаб/списки.json`:
сделанное вычёркивается само, по следу в коде и в записях git.

| Что | Важность | Заметка штаба |
|---|---|---|
| Сторож простоя ругается на исполнителей, которых больше нет | потом | 10 сентября сторож написал «оформитель молчит 11 ч 26 мин», а оформитель работал прямо в ту минуту — сторож смотрел на след вчерашнего, давно завершённого. Файл записей мёртвого исполнителя не растёт, и выглядит это ровно как молчание живого. Беда не в числе, а в том, что тревога становится фоновым шумом, — а сторожа заводили как раз чтобы не проглядеть настоящее молчание. Чинить так, чтобы штабу не пришлось помнить об этом руками. Порог «молчит дольше суток — считаем ушедшим» не годится: живой исполнитель тоже ждёт долгую команду молча ⚠️ в записях git есть похожее: «сторож простоя: молчание исполнителя видно в ту же минуту, а не когда спросит владелец» — проверьте, не сделано ли |
| Списки считают сделанным то, что лежит в рабочем дереве | **горит** | 10 сентября программа записала в «Готово» дорогу до нард, потому что исполнитель успел завести функцию в js/game.js. Работа при этом не была ни сдана, ни проверена, ни опубликована — игрок в нарды по-прежнему попасть не мог. Программа сама писала рядом «время из git не нашлось» и всё равно считала дело закрытым. Это ровно та неправда на дашборде, за которую владелец ругал дважды. Чинить так: примета смотрит на опубликованное (git show origin/main:файл), а не на файл на диске; не нашлось времени в git — значит не сделано, дело остаётся в очереди. Сейчас в «Готово» по этой причине висят три строки с пометкой «время из git не нашлось» — проверить каждую ⚠️ в записях git есть похожее: «списки поймали сами себя: сделанным считалось то, что лежит в рабочем дереве» — проверьте, не сделано ли |
| Плитки будущих игр включаются вручную, и про это забывают | потом | нарды были готовы сутки, а плитка на витрине стояла выключенной с подписью «скоро» — попасть в игру было нельзя вовсе. Проверки этого не ловили, потому что заходили на страницу игры напрямую, минуя витрину. Сделать так, чтобы признак «скоро» нельзя было забыть снять: либо плитка сама смотрит, есть ли страница игры, либо есть запуск, который краснеет на «игра есть, а дороги к ней нет» ⚠️ в записях git есть похожее: «на витрине появились четыре будущие игры, а плитки выровнялись по высоте» — проверьте, не сделано ли |
| Разнобой в именах ключей памяти | потом | вибрация лежит под латинским haptics, соседняя настройка — под русским «настольные-игры:последняя». Играть не мешает, но тестировщик уже на этом споткнулся: искал русское имя и решил, что выбор не сохраняется. Через месяц споткнётся человек. Осторожно: переименование ключа стирает выбор игрока, нужен перенос старого значения — так уже делали с рекордами ⚠️ в записях git есть похожее: «шахматы и нарды вписаны в имена ключей — иначе рекорды осиротели бы молча» — проверьте, не сделано ли |
| Один тап «позвать знакомого» | задел | сперва владелец посмотрит на список живьём ⚠️ в записях git есть похожее: «на компьютере «Позвать друга» больше не теряет окно игры» — проверьте, не сделано ли |
| **Четвёртая игра: домино** | задел | владелец 9 сентября попросил список трёх следующих игр. Домино первое: играется компанией 2-4 (у нас сильна игра с друзьями, а шашки и шахматы только вдвоём), правила знают все без объяснений, партия 10 минут. Переиспользует почти всё: столы на 2-6, комнаты, насос ботов, рейтинг. Новое — только сами костяшки и правила |
| Пятая игра: морской бой | задел | самая дешёвая из известных и единственная у нас со скрытой информацией: соперник не видит твоё поле. Идеальна для игры с другом по сети, а расстановка кораблей пальцем — приятная возня, которой в сборнике пока нет. Бот простой, и это нормально: азарт тут в угадывании, а не в силе соперника |
| Карточная игра деберц | задел | просьба владельца 9 сентября. Играется вдвоём или парами вчетвером, 32 карты. Честно о цене: правила заметно сложнее дурака — объявления (терц, пятьдесят, сто), белла, обязательность ходить в масть и перебивать, счёт до 501. Больше всего работы не в правилах, а в том, чтобы человек понимал, почему у него столько очков: без хорошего показа объявлений игра будет казаться произволом. ## Долги команды

**Честно: это не очередь, а список долгов, и он почти не движется.** Каждый
раз, когда владелец просит новое, его просьба справедливо обгоняет уборку —
и правильно. Держим список, чтобы долги не забылись, но не делаем вид, что
они «в очереди на завтра». Берём их, когда нет ни одного «горит» и «скоро».

| Что | Заметка |
|---|---|
| Стенды по шашкам и девять проверок серверщика перенести в `tests/` | ловцы ошибок исчезнут с концом сессии |
| Сервер: три копии «хранилища на диске» свести в одну; словари слов брать из правил | девять замечаний серверщика по уборке |
| Правила: пять склонений в одно, шесть «есть ли дверь» в одно | файл дорос до восьми тысяч строк |
| Вынести правила дурака из `js/game.js` в свой файл | путь у сервера и тестов, порядок подключения у страницы |
| Сверять зерно раздачи дня на сервере | пока результату верим на слово: это счёт, не право |
| Шашки: «спрятать плашку итога» в двух копиях, три копии обёртки настроек | резать, когда появится третий экран или четвёртая копия |
| Шашки берут шесть id у дурака ради его стилей | скрытая связь: переименует оформитель дурака — у шашек слетит вид |

## Решения, принятые штабом без владельца

Чтобы не тормозить работу. Любое можно переиграть — скажите.

| Решение | Почему так |
|---|---|
| Шашки — отдельная страница; сперва только против бота | две игры на одной странице ломают друг друга; общий сервер не открывается |
| Рекорд в шашках — серия побед подряд по уровням; смена уровня серию не рвёт | правило общего хранилища, одно на обе игры |
| Рейтинг сперва личный; экран назван «Как я играю», а не «Рейтинг» | рейтинг — сравнение с другими, которого пока нет |
| **Серии побед в дураке — по уровням отдельно** (9 сентября) | владелец сказал «мне пох», решал штаб. Раньше одно поражение на лёгком гасило серию на сложном: человек набирал её неделю, играл одну расслабленную партию — и терял всё. Наказание за отдых, и без смысла: серия на сложном говорит «я стабильно обыгрываю сильного», партия с лёгким этого не опровергает. Заодно так честнее — три серии меряют три разные вещи, а одна общая не меряет ничего. Совпало с тем, как уже сделано в шашках |
| Список знакомых — только те, с кем правда играл, взаимно; 60 дней, не больше 50 | Telegram не даёт контактов, и правильно делает |
| Токен бота доверен серверу комнат | та же машина; наружу не выходит, зовёт два метода |
| «Ну ты даёшь» в чат не попала | после чужой ошибки читается как насмешка |
| Витрина не пропускается по памяти; незаконченная партия — пометка, не автопереход | витрина, которая сама уводит, — не страница выбора |
| Статистика сервера отдаётся всем, кто спросит | одни счётчики, ни имён, ни номеров |
| Один тап «позвать» не делаем | сперва владелец посмотрит на список живьём |
