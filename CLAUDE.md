# Games — игра для Telegram

Правила здесь короткие и обязательные. Истории «почему» — в `штаб/уроки.md`: читать при споре с правилом, не на каждом шаге.

## Что строим
Telegram Mini App: сборник игр (дурак, шашки, шахматы, нарды…) внутри Telegram, управление пальцем, экран вертикальный. Стек: HTML + CSS + чистый JS без сборки; связь с Telegram — официальный `telegram-web-app.js`; рекорды — CloudStorage с откатом на localStorage; бот-лаунчер на Node; публикация — GitHub Pages (пуш = публикация). **Никаких фреймворков и сборщиков без отдельного решения штаба.**

## Штабу
Правила штаба (команда и модели, ритм, надзор, лимит, списки и дашборд, «первая версия готова, когда») — в `штаб/правила-штаба.md`. Читает их только штаб: на старте и после каждого сжатия памяти. Исполнителю этот файл не нужен.

## Язык
Всё по-русски: общение, комментарии, коммиты, тексты игры. Просто, без жаргона; термин — сразу с расшифровкой.

## Команда
**Штаб** (главная сессия) кода не пишет никогда: режет задачи, пишет задания, принимает работу, коммитит. Исполнители: developer (код строго по заданию, только названные файлы), designer (вид НОВЫХ экранов, только файлы оформления), reviewer (только чтение), tester (пишет только в tests/), playtester (только браузер), джо (новая игра, только `штаб/игры/<игра>/`). Исполнитель не коммитит.

- Оформителя звать только на новый экран; косметику делает разработчик (вид — всё равно в файлах оформления).
- **Один файл — один исполнитель.** Файлы распределяются в задании вслух. Понадобился чужой файл — исполнитель останавливается и спрашивает штаб.

## Проверяющие
- Браузеров проверок — не больше трёх разом и только пока свободно ≥ 3 ГБ памяти (владелец 24.09; раньше был один — машина падала). Перед каждым браузерным запуском — `node штаб/браузер-занят.js` (код 1 — занято; `--ждать` ждёт до 20 минут). Считаются только безголовые браузеры проверок, не node-скрипты.
- Playtester'у штаб заранее даёт ссылку `http://…` — файлы с диска браузер-робот не открывает.
- **Каждая проверка обязана уметь краснеть**: к ней делается ломающий запуск, который портит проверяемое и требует провала.
- **Ломающий запуск портит КОПИЮ, а не файл проекта.** Копия — во временной папке исполнителя, путь к ней проверка получает доводом. Настоящий файл не портят даже «на минуту».
- **Исполнитель не откатывает файлы проекта.** `git checkout`, `git restore`, `git stash` на файле проекта стирают чужую несохранённую работу: в одном файле к вечеру лежат незакоммиченные правки сразу нескольких исполнителей, и откат уносит их все разом. Испортил настоящий файл — не откатывай, а скажи штабу и назови путь к своей копии.
- **Ноль найденного — это провал, а не пропуск.** Не нашла узел — краснеет. `if (нашлось) { проверяем }` превращает проверку в украшение: узел переименовали, поиск вернул ноль, проверка отчиталась «всё хорошо». Спрашивать не «сколько пунктов зелено», а «на какой настоящей поломке она покраснела».
- **Меняешь приём — обновляй проверку тем же коммитом.** Проверка читает устройство из того же файла, что и рисует его. При перестройке ищи проверки по именам затронутых узлов, не жди покраснения.
- `\b` в regex не знает кириллицы: /--я\b/ молча не найдёт «место-за-столом--я». Проверка, нашедшая ноль, обязана быть подозрительной.
- Штаб картинки не открывает. Снимок оценивает смотритель, штаб получает его текст.

## Время
- **Время только из команды** (date, git log, время файла). Порядок жёсткий: сперва команда со временем, запись — следующим ходом, не параллельно.

## Команды
- Одна команда — одно действие, коротко. Запрещены: `rm -rf`, `tar`, `python` (только node), широкие `taskkill`, цепочки через `&&`/`;`. Длинный текст — в файл, команда читает файл.
- **Склейка — это и перевод строки тоже.** `cd` + `mkdir` + `cp` + `node -e` + `rm` в одном вызове, разделённые переносами, — такая же склейка, как через `&&`: целиком она не подходит ни под одно разрешение и будит владельца окном «разрешить?». Владелец пожаловался на это 21.09. Штаб пишет запрет прямо в каждое задание.
- Безобидные команды разрешает сам привратник `.claude/hooks/разрешение-команд.js`: он пропускает всё, кроме необратимого (снос папок, откат git, `--force`), секретов (`.env`), боевого порта 8790 и широкого убийства процессов. Запрещать он не умеет — на опасном просто молчит, и спрашивают владельца, как раньше. Проверка себя: `node .claude/hooks/разрешение-команд.js --проверить`.
- Частое действие — маленькая программа в `штаб/` (перезапуск-сервера.js, перезапуск-дашборда.js, в-работе.js, важное.js, списки.js, расход.js).
- Боевой сервер комнат 8790 не перезапускают исполнители; штаб — только посмотрев, сколько комнат живо. Тестовые копии — на других портах, гасить по PID.

## Код и вид
- **Корень проекта чистый** (правило владельца 16.09, ужесточено 09.10): в корне только страницы (html), CLAUDE.md, README.md, ЗАДАЧИ.md, эталон-вида.md, robots.txt, sitemap.xml и запуск. Ни одного css и js в корне, папки `js/` в корне нет. Снимки — только в tests/снимки/ (или снимки/), черновики и разовые скрипты — в scratchpad сессии, не в проекте. Проверка tests/корень-чистый.js краснеет на любом лишнем файле в корне.
- **У каждой игры своя папка** (владелец 09.10: «чтобы более не было такого бардака»): оформление, js и языки игры лежат в `игры/<игра>/`, имя папки = имя страницы без .html. В `общее/` — только то, что просят две игры и больше (`общее/js/`, `общее/css/`, `общее/casual/`, `общее/шрифты/`). Новый файл игры — сразу в её папку; «временно в общее» не бывает. Служебные скрипты — `штаб/скрипты/`, заметки — `штаб/заметки/`.
- **Разработчик не задаёт вид из кода**: из js — только классы и данные (CSS-переменные-числа). Размеры, цвета, отступы — файлы оформителя.
- **Разметка не уезжает раньше файлов**: новый js/картинка и строка подключения — одним коммитом. Новый файл подключает штаб при приёме. Номера `?v=` поднимает штаб, у ВСЕХ страниц, которые просят изменённый общий файл (разъезд номеров = игроки со старым кэшем).
- `.gitignore` прячет снимки, но картинки игры под `img/**` разрешены явно. «Работает на стенде» ≠ «доехало»: проверять опубликованный адрес.

## Все игры выглядят одинаково (правило владельца)
- Общая ширина колонки и поля; тёмная страница, один салатовый акцент; дерево и сукно только внутри стола/доски, плоская заливка запрещена; эталоны — наборы владельца в `эталон/`.
- Верхняя строка «‹ ⋯» (в Telegram её заменяют системная стрелка и пункт «Настройки» — привязку делает КАЖДАЯ страница); один общий лист «⋯» (общее/js/лист-ещё.js), порядок строк: В меню · Как играть · Звук · Вибрация · Оформление · Рекорды; чего у игры нет — той строки нет.
- Нижняя полоса «Игры · Рейтинг · Профиль» (общее/js/нижние-вкладки.js; первая вкладка — «Игры», ведёт на витрину, владелец 21.09) на домашних экранах, не поверх партии. Мёртвых вкладок и кнопок не бывает: чего нет — честное «скоро» или отсутствие.
- Лобби каждой игры: id `экран-лобби`, каркас дурака (заголовок, профиль, картинка-гнездо, карточки входов, «Есть код?», полоса). Настроек мало — всё в лобби одним экраном; много (дурак) — три шага. «Как играть» доступна ДО партии.
- Новая игра своего вида не рисует: берёт общие классы; недостающее оформитель добавляет в общий файл.
- **Рейтинг есть у каждой сетевой игры и игры со счётом** (владелец 26.09; уточнение 29.09 21:33: одиночные игры без счёта — пасьянсы, маджонг, сапёр, японский кроссворд, поиск слов, пятнашки — без рейтинга, у них в реестре поле `безРейтинга` с причиной): новая игра — запись в `общее/js/игры-реестр.js`, общая полоса с «Рейтингом» и экран `рейтинг-экран.js`. `tests/у-каждой-игры-рейтинг.js` не пустит игру без этого; список ДОЛГ в ней только сокращают. Блоки, три в ряд и змейка спрятаны с витрины и из выбора игр рейтинга (владелец 29.09), вернутся отдельной задачей.
- **Экран не сдаётся без снимка** — снимок оценивает смотритель, штаб сам картинку не открывает.

## Коммиты и готовность
- Коммит после каждого принятого этапа, по-русски, понятно через месяц. Незаконченное не коммитим.
- Этап принят, только если: 1) код запускается, консоль чистая, старое не сломано; 2) есть повторяемая проверка, описанная шагами; 3) штаб принял, замечания ревьюера исправлены или сознательно отложены с записью.

## Структура
```
index.html и страницы игр (*.html) — в корне
игры/<игра>/ (оформление, js и языки одной игры; игры/дурак/ — game.js, дурак-путь.js)
общее/js/ (telegram.js, сеть.js, лист-ещё.js, нижние-вкладки.js, рейтинг-экран.js, игры-реестр.js…)  общее/css/ (style.css…)  общее/casual/  общее/шрифты/
server/ (сервер.js, комнаты.js, партия-по-сети.js, игры/, билеты.js, рейтинг.js)
tests/  штаб/ (правила работы, планы, дашборд, программы)  эталон/  img/  bot/ (токен в bot/.env)
```

## Договоры (границы, которые не размывают)
- `общее/js/telegram.js` наружу: saveScore(n), loadScore(), isReady() — game.js больше ничего про Telegram не знает.
- `общее/js/сеть.js` — единственное место браузера, знающее сервер, коды и пропуска; наружу window.Сеть, состояние стола — через ИграПоСети.показатьВид.
- **Правила игр не раздваиваются**: сервер require'ит те же `игры/<игра>/*-правила.js`, что браузер. Правишь правила — правишь обе стороны.
- **Клиенту не верим**: всё, что уходит игроку, собирается вручную поле за полем в `видДляИгрока` (server/партия-по-сети.js). Новые поля — только там.
- Ключи памяти игрока — только латиница, не переименовывать; новый ключ — через Телеграм.перенестиНастройку.

## Безопасность
Токены и ключи — только в `.env` вне git. В коде и чате токенов не бывает. Нужен новый секрет — спросить владельца.
