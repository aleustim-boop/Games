## Ловушки, о которых забывают (все стреляли)
- Ревьюер на полной модели окупается на сервере: поймал утечку тестового флага в свободныйКод() (server/комнаты.js) — без ревью форсированный код мог тихо перезаписать живую комнату при утечке в несвязанный вызов.
- «Один файл — один исполнитель» держится только текстом: tester ночью 18.09 дважды дописывал в чужой server/комнаты.js вместо tests/ — штаб поймал через git diff. Разработчик Этапа 4 «друзья» столкнулся с этим же ограничением честно: index.html не входил в его файлы, поэтому вход на экран (кнопка «Мои друзья», оживление пары «Круг игроков») сделан программной достройкой DOM в рантайме (js/рейтинг-экран.js), а не правкой чужой разметки — приём одобрен ревьюером.
- Каждая проверка обязана уметь краснеть по-настоящему: не верить зелёному на слово, проверять флагом `--сломать`.
- Личная проверка кода выхода через pipe лжёт: `cmd | tail; echo $?` возвращает код `tail`, а не `cmd`. Проверять без pipe: `cmd > файл 2>&1; echo $?`.
- Разработчик может сдать правку общего js-файла и забыть поднять «?v=» — штаб при приёме ОБЯЗАН отдельно проверить `grep -rn "файл.js?v=" *.html` до коммита, не полагаясь на дифф разработчика. Файл может быть подключён на ЧЕТЫРЁХ страницах разом (index/нарды/шахматы/шашки) — поднимать номер везде, не только там, где менялась разметка.
- Уведомления о завершении фоновой задачи могут прилететь повторно спустя часы или даже дни после реальной сдачи и коммита (видено на tests/застолье-рейтинга-правило.js, на 18.09-ночных задачах про кнопку «В меню» шашек и стенд tests/кнопки-назад-везде.js, и снова 20.09 — те же две плюс дубль по тестировщику «2 на 2», все три уже закрыты коммитами 0280876/d1029db/8bb939f/9131c48). Перед тем как переоткрывать работу по уведомлению — сверить `git log -- <файл>` и дату коммита с датой уведомления; коммит старше — это дубль, действие не нужно.
- Публикация клиентских файлов через GitHub Pages не мгновенна: после пуша страница может отдавать старую версию ещё минуту-две. Не поверить первому 404/старому содержимому — подождать и сверить побайтово (`diff`/`wc -c`) заново, а не гадать по одному запросу.
