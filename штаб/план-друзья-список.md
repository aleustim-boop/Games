# План: список друзей для рейтинга

Утверждено штабом 19 сентября (опись — агент, задача «Опись и план: список друзей
для рейтинга», лично проверено штабом через grep по коду). Не начинать кодирование
до ответа владельца на открытые вопросы (штаб/важное.json).

## Главный вывод разведки

Списка контактов Telegram мини-приложению не даёт (и не может — Bot API это не
отдаёт). «Список друзей» может быть только свой, внутриигровой: добавление по
коду/ссылке и взаимное подтверждение. `server/знакомые.js` — близкий по устройству
файл («с кем играл»), но семантически другой: автоматический, забывается через
60 дней, без статуса заявки. Архитектуру хранения стоит скопировать, модель данных —
другая (статус пары: заявка/друзья).

## Опись — что есть сейчас

- `js/telegram.js`: `имяИгрока()` берёт имя из `initDataUnsafe.user`, наружу не
  отдаёт id/фото — двери «кто я» для других файлов нет, и не нужна (сервер сам
  проверяет `initData`).
- `server/сервер.js`: `ктоПрислал/ктоПодписал` (961) — единственный источник
  истины «кто это». Образец готовой двери — `/знакомые` → `списокЗнакомых` (1299):
  номера Telegram наружу не уходят, вместо них одноразовый `ключДруга` (HMAC,
  секрет новый при перезапуске). Образец действия по ключу — `/позвать` (1592).
- `server/знакомые.js`: `ключПары(номер1, номер2)` — одна запись на пару,
  взаимность бесплатно (меньший:больший номер); отложенная запись на диск через
  временный файл + `renameSync`; `включитьЗапись()` для тестов. Архитектурный
  образец для нового файла.
- `server/комнаты.js`: код комнаты — 4 знака без похожих символов (0/O/1/I),
  `новыйКод()` (260). `server/шлагбаум.js` — задержка ответа против перебора
  коротких кодов, привязана к IP, не общему счётчику. `server/не-звать.js` —
  образец «отказа, который переживает перезапуск» (номер → причина, свой JSON).
- `js/рейтинг-экран.js` + `index.html:721`: фильтр «Друзья» — честный disabled,
  «скоро». `решение()` уже умеет читать альтернативный срез (`поПравилу`) —
  тот же паттерн «сервер присылает несколько срезов, клиент переключает».
- `server/рейтинг.js`: свежий образец второй оси (`поПравилу`, план
  «рейтинг-правило», 19.09) — но фильтр «друзья» не ложится тем же способом:
  это не счёт самого игрока, а выборка ДРУГИХ строк по списку его друзей.
  Нужен отдельный приём: сервер берёт список номеров друзей → находит их записи
  в таблице по номеру → строит верхушку только среди них (образец —
  `списокЗнакомых`, тот же принцип обхода списка номеров).
- Чего нет вовсе: хранилища связей с заявкой, способа узнать номер того, кого
  добавляешь, экрана «Мои друзья», маршрутов `/друзья-*`, среза рейтинга по
  списку номеров.

## Решения владельца (20.09, 09:14–09:15)

- **Способ добавления — сперва кнопка «Добавить в друзья» у уже существующего
  списка «с кем играл»** (`server/знакомые.js`), рекомендация штаба принята
  (штаб/важное.json, ключ `друзья-способ-добавления`). Код/ссылка — не в этом
  плане; если станет мало (нужно добавить того, с кем ещё не играли), это
  отдельная будущая задача поверх готового.
- **Нужен полноценный экран «Мои друзья»** (ключ `друзья-назначение-экрана`) —
  этап 5 остаётся в работе, не вырезается.

## Этапы

**Этап 1 — `server/друзья.js` (новый файл).** Хранилище связей: статус пары
(`ожидает`/`друзья`), кто позвал, когда. Взаимность тем же приёмом, что у
знакомых — одна запись на пару. Функции: `позватьВДрузья`, `принятьЗаявку`,
`отклонитьЗаявку`, `удалитьДруга`, `друзьяИгрока`, `входящиеЗаявки`. Без срока
давности (это не «знакомые» — забвения нет). Ревьюер обязателен (новый файл
с диском). Тестировщик — node-скрипт по образцу теста знакомых, если есть.

Принято штабом 20.09 09:28 (ревью — вердикт «принять»). Мелкое замечание
ревьюера сознательно отложено: `прибраться()` при переполнении потолка (300
на человека, практически недостижим) сортирует записи на удаление только по
давности, не отделяя статус «ожидает» от «друзья» — теоретически можно снести
старую дружбу раньше давно висящей заявки. Не блокирует; если понадобится —
поправить по образцу приоритета в `server/не-звать.js:196-204`.

**Этап 2 — `server/сервер.js`: способ добавить друга.** Решено — кнопка
«Добавить в друзья» у уже существующего списка «с кем играл» (§1.3), номер
адресата берётся из уже известной пары знакомых — свой код/шлагбаум не
нужен, перебирать нечего (список знакомых сам по себе закрыт от посторонних:
отдаётся только подписанному владельцу пары через `/знакомые`). Маршруты
`/друзья-позвать` (принимает номер из списка знакомых игрока, не с воли),
`/друзья-принять`, `/друзья-отклонить`, `/друзья-удалить`, `/друзья-список` —
по образцу `/знакомые`, номера наружу не уходят. Ревьюер обязателен (сервер,
общий файл).

**Этап 3 — `server/рейтинг.js`: срез «только друзья».** Новая функция
`срезПоСписку(игра, номер, списокНомеров)` — строит верхушку/своё место среди
списка номеров + сам игрок. Дневные потолки и начисление очков не трогает —
только фильтрует, кого показывать. Ревьюер обязателен (сервер).

**Этап 4 — `js/рейтинг-экран.js`: подключить фильтр.** Снять disabled у пары
«Все игроки/Друзья», по образцу уже сделанного для «Подкидной/Переводной».
Пустой список друзей — честная фраза, не пустая таблица. Зависит от этапа 5
разметкой (ссылка «Добавить друга»).

**Этап 5 — новый экран «Мои друзья».** `index.html` + новый `js/друзья-экран.js`.
Список, входящие заявки, кнопка «Добавить друга» (код и/или диплинк). Designer —
если экран действительно новый по виду (решает штаб при раздаче). Обязателен
снимок при сдаче.

## Явно вне рамок

Импорт контактов из Telegram (технически невозможен). Расширение
`server/знакомые.js` под дружбу (другая сущность, другой смысл — трогаем только
чтением, если владелец решит их когда-то связать). Рейтинг «2 на 2» — отдельный
план. Уведомления от бота о заявке в друзья — можно сделать тем же приёмом, что
и «Позвать знакомого», но отдельным пунктом, не молча.

## Открытые вопросы — решены владельцем 20.09

Оба вопроса решены, см. раздел «Решения владельца» выше и записи
`друзья-способ-добавления`/`друзья-назначение-экрана` в штаб/важное.json.
Заодно решение по способу добавления сняло развилку «заявка в пустоту
незарегистрированному» (§4 п.4 отчёта агента): раз добавить можно только
того, кто уже есть в списке «с кем играл», адресат по определению уже хотя
бы раз открывал игру. Остальные развилки агента (лимит числа друзей,
«остывание» отказа, уведомления от бота) штаб решает разумным умолчанием
без отдельного вопроса: без автозабвения (иначе дубликат «знакомых»),
верхний потолок 300 на человека (щедрый технический предел, не поведенческое
ограничение), отказ не «остывает»
сам (тот же принцип, что у «не-звать» — отказ бессрочный, пока не позовут
заново явно), уведомления от бота — не делаем в этом плане, отдельным пунктом
позже при желании владельца.
