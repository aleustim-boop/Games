# План: рейтинг-эталон во всех играх — нынешних и будущих

Просьба владельца 26.09 09:51: «нужно что бы эталон рейтинга работал во всех играх которые есть и которые будут созданы в будущем».

## Что сейчас (опись 26.09 09:55)
- Эталон — js/рейтинг-экран.js. Подключён на 9 страницах из 11.
- **2048** — рейтинга нет вовсе (ни экрана, ни вкладки, ни очков). Игру ведёт другая сессия: её файлы (2048.html, js/2048-*.js, style-2048.css) — только по согласованию.
- **Монополия** — экран подключён, но входа нет: своя нижняя полоса mono-footer вместо общей «Лобби · Рейтинг · Профиль».
- **Шахматы** — вход есть, таблица всегда пуста: серверной игры нет, партии с ботом очков не дают.
- Партии с ботом дают очки только в дураке (server/билеты.js:60–62, ИГРЫ_С_БИЛЕТАМИ).
- Списка игр для рейтинга нет в одном месте. Он вписан руками примерно в 10 местах: РЕЕСТР_ИГР в js/рейтинг-экран.js:225, ИГРЫ в server/игры/умолчания.js:14, ИГРЫ_С_БИЛЕТАМИ, МЕТКИ_ИГР, наборы вкладок и прочие. Поэтому новая игра рейтинг не получает.

## Этапы
- **Э1. Один реестр игр и сторож.** Новый js/игры-реестр.js, который читают и страница, и node. В нём для каждой игры: ключ, падежи, страница, вес для «силы», способ очков (`сеть` / `билет` / `нет`). РЕЕСТР_ИГР в рейтинг-экран.js и ИГРЫ в server/игры/умолчания.js берутся из него, поведение не меняется. Проверка tests/у-каждой-игры-рейтинг.js — трещотка: каждая плитка витрины и каждая страница игры обязаны иметь запись в реестре, подключённый рейтинг-экран.js и вкладку «Рейтинг». Нынешние дыры (2048, монополия, шахматы) лежат в списке ДОЛГ. Проверка краснеет:
  - на новой игре без рейтинга;
  - на игре из ДОЛГа, которую уже починили, но из списка не вычеркнули. Так список ДОЛГ может только уменьшаться.
- **Э2. Монополия: общая нижняя полоса с вкладкой «Рейтинг».** Файлы монополии — по согласованию с её сессией; если сессии нет — делает наш разработчик.
- **Э3. Партии с ботом дают очки во всех играх** (как в дураке, через билеты). Ждёт ответа владельца (вопрос «рейтинг-партии-с-ботом»). Закрывает пустую таблицу шахмат.
- **Э4. 2048 в рейтинге.** Экран, вкладка, запись в реестре. Как считать очки — ответ владельца. Делает сессия 2048 или наш разработчик после её коммита.
- **Э5. Правило для новых игр.** В CLAUDE.md, раздел «Все игры выглядят одинаково», одна строка: новая игра — запись в js/игры-реестр.js. Проверка у-каждой-игры-рейтинг.js сама не пустит игру без рейтинга.

## Решения штаба
- Строки таблицы, подиум и вкладки мер — общие для всех игр, как в эталоне. Своих таблиц у игр нет.
- Реестр — только данные; вид из него не задаётся.
- Сервер на Э1 не меняет поведения, поэтому перезапуск ВМ не обязателен. Ревьюер нужен всё равно: правка общих файлов.
