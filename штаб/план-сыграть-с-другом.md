## 2. Решения, принятые по умолчанию (см. вопросы в конце)

### 2.1 Одна таблица игр на сервере
Новый файл `server/игры/названия.js`: для каждой из 8 сетевых игр — `метка` (латиница из js/сеть.js:152), `страница`, `вИгру` («в нарды», «в подкидного дурака», «в деберц»…), `заСтолом` («за столом в нардах»). Все regex меток в сервер.js и лента.js строятся из неё; новые игры добавляются одной строкой.

### 2.2 Ссылка с id приглашения (старые продолжают работать)
Сервер выдаёт id при подготовке приглашения. Формат startapp: `<метка_>КОД-<адрес>` + необязательный хвост `.<id>`, где id — 8 символов [a-z0-9]. Хвост отделяется точкой — её нет ни в base64url, ни в кодах. Ссылка без хвоста разбирается как раньше. Длина startapp ≤ 64 символов проверяется в тесте: если адрес длинный, id не добавляется, а приглашение учитывается без события «вход по ссылке».

### 2.3 Учёт приглашений
- Файл данных: `приглашения.json` в папке данных (server/папка-данных.js; для проверок её уводит ДАННЫЕ_ИГРЫ). Формат — объект `{ "<id>": { создано, кто (Telegram ID), игра, код, комнатаСоздана, тест, события: [{что, когда, кто?}] } }`.
- События: `создано`, `окноОткрыто` (клиент открыл shareMessage или окно выбора чата), `скопировано` (запасной путь — буфер), `отправлено` (только колбэк shareMessage с sent=true), `отменено` (колбэк с false), `вход` (сервер посадил человека по этому id), `старт` (раздача первой партии с этим человеком), `итог` (учестьИтогПартии). `окноОткрыто/скопировано/отправлено/отменено` — со слов клиента, помечаются `соСловКлиента: true`; `вход/старт/итог` ставит только сервер.
- Хранение 60 дней, запись отложенная через временный файл (как статистика.js), запись на диск — только после включитьЗапись().
- Перезапуск сервера: комнаты живут в памяти и теряются. Запись приглашения остаётся; ссылка с её id после перезапуска даёт отказ «закрыта», событие «вход» не наступит. При старте сервер закрывает открытые записи событием `комнатаПотеряна` (по полю `комнатаСоздана` старее старта процесса). Это честно показывает, сколько приглашений сгорело от перезапуска.

### 2.4 Метка тестовых действий
- Список тестовых Telegram ID — `тестовые.json` в папке данных (массив чисел; заполняет владелец/штаб, в git не кладётся). Всё, что пришло от такого ID, пишется с `тест: true`; в статистике — в отдельные счётчики с приставкой `тест-`.
- Проверки на node всегда уводят данные во временную папку через ДАННЫЕ_ИГРЫ — в боевые файлы не попадают.
- Отчёт по учёту по умолчанию считает без `тест: true`.

### 2.5 Правки видДляИгрока
Минимальные, во всех восьми (server/партия-по-сети.js и server/игры/*.js): у каждого места в `застолом` поле `наСвязи` (если его нет) — нужно нардам вместо жёсткого «В сети». Флаги друзей в вид НЕ добавляются: они идут отдельной дверью `/друзья-за-столом` (п. Э7), чтобы не раздувать восемь адаптеров и не отдавать ключи всем при каждом опросе. Telegram ID соседей в вид не попадают.

### 2.6 Причины отказа входа
`вход.почему`: `закрыта` (код устарел или комнаты нет после перезапуска), `заполнена`, `идёт` (партия началась), `нет` (код не найден). Сервер /войти отвечает 403 с полями `{ ошибка, почему }`; клиент показывает причину и кнопки «Создать новый стол» (ведёт в лобби этой игры с открытием создания) и «В лобби».

### 2.7 Один аккаунт — одно место
В войтиВКомнату и сестьЗаСтол: если в комнате уже сидит игрок с тем же подтверждённым `телеграм`, возвращается его место и новый пропуск (старый пропуск перестаёт действовать — второе устройство выпадает с «Вы вошли с другого устройства»). Без подтверждённого ID работает старая логика по метке. В рейтинге пары с одинаковым номером пропускаются, а партия, где все места — один номер, не учитывается вовсе.

## 4. Только на двух настоящих Telegram-аккаунтах
1. shareMessage: подготовленное сообщение уходит в выбранный чат, колбэк sent=true доходит и пишется «отправлено»; отмена даёт «отменено».
2. Друг без открытого ранее приложения жмёт кнопку в чате → после первого запуска (согласие, заставка) попадает прямо за стол нужной игры — для всех 8.
3. Название игры в пузыре сообщения, в кнопке и в уведомлении ленты от бота совпадает с комнатой.
4. Один аккаунт с телефона и с компьютера в одной комнате — одно место, второе устройство получает «вы вошли с другого устройства».
5. Реванш и «Добавить в друзья» на результате: заявка приходит второму аккаунту, принимается.
6. Старая ссылка (разосланная до выкладки) открывает стол, если комната жива.
7. После перезапуска боевого сервера ссылка даёт «Стол закрыт» и кнопку нового стола.

## 5. Вопросы (план написан с вариантом по умолчанию)
1. Формат id в ссылке — хвост `.id` в startapp? По умолчанию: да; при нехватке длины — без id.
2. Тестовые ID — файл `тестовые.json` в папке данных, заполняет штаб? По умолчанию: да.
3. Второе устройство того же аккаунта — выбивать первое (новый пропуск) или отказывать второму? По умолчанию: выбивать первое.
4. Деберц создаёт стол открытым (чужой может занять место друга) — делать закрытым при «Пригласить друга»? По умолчанию: закрытый при приглашении, открытый — только через «Открытые столы»; этап не заведён, ждёт решения.
5. «Поделиться приложением» — ссылка без игры, но с id пригласившего для учёта? По умолчанию: только текст и подпись, без учёта (учёт — у приглашений за стол).
