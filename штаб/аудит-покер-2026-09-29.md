# Покер: проверка и исправления 29 сентября 2026

Проверены движок техасского холдема, боты, серверные комнаты, подбор соперника, интерфейс, сохранения и завершение партий. Ниже — результаты реально запущенных проверок, а не обещание отсутствия любых ошибок.

## Найдено и исправлено

- Очерёдность блайндов после выбывания: новые партии используют dead button, чтобы участник не пропускал большой блайнд. Старые сохранения воспроизводятся по прежней версии правил.
- При коротком ва-банке большого блайнда оставшийся игрок больше не обязан доплачивать номинальный блайнд без соперника, способного ответить.
- Сервер отклоняет повторные и запоздалые действия с устаревшей версией состояния.
- Подбор на двоих правильно передаёт имена и признак бота; замена ушедшего человека ботом обозначается явно.
- Обновления онлайн-партии больше не вытаскивают пользователя из лобби. Есть возврат за текущий стол; переход к локальной партии предупреждает о выходе из онлайн-стола.
- После ошибки сети кнопки ставки снова доступны. На время запроса повторное нажатие заблокировано.
- Исправлены ожидание согласий на реванш, выход выбывшего игрока и отмена партии после ухода соперника без выдуманного победителя.
- Итог раздачи вынесен из области карт. Доступны подробности основных/побочных банков, возврат непринятой ставки и открытые комбинации. Сброшенные чужие карты остаются скрытыми.
- В горизонтальном Telegram-окне с большими безопасными отступами общие карты больше не накладываются на собственные. Аватар игрока остаётся видимым.
- Повреждённое сохранение показывает понятную ошибку и не мешает начать новую партию.

Основные файлы: `js/покер-правила.js`, `js/покер-экран.js`, `server/игры/покер.js`, `server/комнаты.js`, `style-покер.css`, `покер.html`.

## Ограничения проверки

- Два реальных Telegram-аккаунта и физические телефоны не использовались. Telegram API и безопасные отступы проверены подделкой API в Chromium. Сетевые партии действительно выполнялись через сервер, а не только через нарисованное состояние интерфейса.
- Сценарии задержанного и неуспешного запроса проверены управляемой имитацией. Все варианты мобильной связи и поведения Telegram WebView этим не покрываются.
- Стресс-тест большого числа одновременно работающих комнат не проводился.
- Сервер хранит активные партии в памяти; его перезапуск может прервать их. Публикация серверных исправлений должна выполняться после освобождения комнат.
- Реальным пользователям сообщения не отправлялись. Тестовые аккаунты и данные изолированы от пользовательской базы.
