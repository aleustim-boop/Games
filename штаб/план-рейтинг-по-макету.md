## 3. Опись: что берём, что переделываем, что спорно

### 3.1 Берём как есть (споров нет)

1. Порядок экрана: заголовок → селектор игры → «Все игроки/Друзья» →
   «Лидеры» → таблица → «Моё место». Это почти то, что у нас построено.
2. Панель выбора игры с поиском, «Все игры» первым пунктом и галочкой
   у выбранного. Панель у нас уже есть — добавится один пункт.
3. Формула общего рейтинга: сумма очков по играм (решение владельца
   совпало с `docs/01`).
4. Сортировка: очки по убыванию, равенство разрешается устойчиво
   (у нас уже есть `сравнитьЗаписи` — надо просто записать правило).
5. Числа с пробелами-разделителями и одинаковой шириной цифр, длинные
   имена — многоточием.
6. Состояния: загрузка / ошибка / пусто / новичок («место —, очки 0»)
   / нет фото → инициалы. Почти всё это уже умеет `видПоОтвету`.
7. Возврат: место входа запоминается при входе и не меняется при смене
   игры; открытая панель закрывается первым «Назад».
8. Золотая палитра макета (фон #070708, поверхность #141416, золото
   #e1c27c, зелёная/красная стрелки) — но только внутри экрана рейтинга.

### 3.2 Переделываем под наши правила

1. **Плотности картинок.** 3x не берём вовсе (вес), только 1x+2x и только
   то, что реально видно на экране.
2. **Демо-портреты не берём.** Чужих фото у нас взять негде (см. 4.5) —
   у всех, кроме себя, инициалы/человечек. Макет это прямо разрешает.
3. **`contracts.ts` не подключаем** — TypeScript. Имена полей остаются
   нашими русскими (`место`, `очки`, `побед`, `партий`, `этоЯ`).
4. **Маршрут.** Вместо `GET /api/leaderboard?game=all` — наше поле
   `игра: 'все'` в уже существующей двери `/рейтинг`. Новый REST не заводим.
5. **Раскладки 768 и 1200 не делаем.** Проект — вертикальный телефон;
   широкий экран получает ту же колонку (сейчас до 520 точек).
6. **Подиум 2–1–3 рисуем кодом**: кружки аватаров, цифры текстом,
   основание подиума — CSS. Кубок у нас уже есть значком (`--значок-кубок`).
   PNG-медали и корона — отдельным шагом и только по решению штаба.
7. **Раздел «Скоро» в панели игр не добавляем** — у нас правило «мёртвых
   пунктов не бывает». Домино и морского боя в проекте нет.
8. **Вкладку «Друзья» не прячем** — у нас дружба настоящая
   (`server/друзья.js`), макет требует прятать только выдуманную.

## 4. Чего НЕ ХВАТАЕТ на сервере (честно)

1. **Общего среза «все игры».** Данные есть (таблицы по играм +
   `умолчания.известныеИгры()`), но функции, которая сложит очки игрока по
   играм и построит общий порядок, нет. Это новая работа в `server/рейтинг.js`.
2. **Суммы по друзьям в общем рейтинге.** То же самое для круга «Друзья»:
   сейчас срез по списку друзей умеет только одну игру.
3. **Места в общем рейтинге.** Сегодня место считается внутри игры;
   общее место — новое число, его никто не считает.
4. **Движения места за сутки.** Вчерашних мест не хранится вообще
   (в `рейтинг.json` только текущие очки). Стрелку взять неоткуда.
5. **Чужих фотографий.** Telegram отдаёт мини-аппу фото только своего
   игрока. Ряды портретов из макета недостижимы принципиально, а не по лени.
6. **Защиты от двойного начисления одной партии** (в макете —
   `RatingEvent` с уникальным ключом). `учестьПартию` начисляет по факту
   вызова; сейчас спасает то, что комната завершается один раз и билет
   бота одноразовый, но отдельного ключа события нет. Это надо либо
   принять письменно, либо чинить отдельным этапом — молча выдавать за
   готовое нельзя.
7. **Длинного списка и пагинации.** Сервер отдаёт верхушку 5 + окно 11
   вокруг игрока. Для макетного «длинного списка с догрузкой» срез надо
   расширять.
8. **Поля «игра даёт очки в общий рейтинг»** (`contributesToGlobal`) и
   статуса игры. Для первой версии считаем, что все четыре дают.

1. **Экран рейтинга общий для четырёх игр.** Сломаю — сломаю сразу

### Доводка золота: код принят 22.09 13:21, ждёт снимка

Разработчик (первый заход, 12:56–13:13): золото `#e1c27c → #e6b34a`
(подобрано по пикселям чисел в макете), подпись «МОЁ МЕСТО» через

`--рейтинг-золото-текст-тёмный`. Заодно синхронизировал вторую копию золота
в `.рейтинг-панель-игр` — штаб принял, но завёл в очередь «свести к одному
месту правды» (запись 48). Мои прогоны: снимок 14/0, экран 361/0,
версии 58/0. Смотритель: числа и кнопки — как в макете, рамка и подпись
есть, КОЛЬЦА У АВАТАРА НЕТ.

Причина (второй разработчик, 13:16–13:21, подтверждена цитатой):
`-webkit-mask: var(--значок-аватар) center / contain no-repeat` в базовом
`.рейтинг-строка::before` обрезает весь рендер, включая `box-shadow`.
Вычисленный стиль тень показывал, экран — нет. Решение: кольцо вложено
вторым слоем самой маски (`radial-gradient` 13–15px в боксе 32×32, значок
ужат до 28px), `style.css:12084–12097`; у настоящего фото (`--фото`,
маска снята) кольцо остаётся `box-shadow`. Скобки 1383/1383, экран 361/0.
Браузер разработчику не давали — занят тестировщиком.

Урок для проверок: «стиль вычислен» ≠ «нарисовано». Пункт про кольцо
тестировщик пишет по пикселям снимка, не по `getComputedStyle`.
