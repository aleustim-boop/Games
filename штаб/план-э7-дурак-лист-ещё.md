# Э7: дурак переезжает на общий js/лист-ещё.js

Опись сделана 17.09.2026 по коду на день написания. Это план-документ для

## 1. Что в game.js сейчас держит лист партии (лист-игры)

Всё это — лист СТОЛА/партии (id `лист-игры`), не витринный лист (см. п.3).

Функции/переменные, которые обслуживают именно его:
- `листИгрыОткрыт()` (game.js:10849) — открыт ли.
- `кнопкаОткрывшаяЛистИгры` (game.js:10856) — переменная, куда вернуть фокус.
- `открытьЛистИгры()` (game.js:10865) — открытие: показывает состояние
  звука/вибрации, решает видимость «В меню» через `этоЭкранИгры()`,
  видимость «Вибрация» через `вибрацияДоступна()`, ищет открывшую кнопку.
- `закрытьЛистИгры(вернутьФокус)` (game.js:10885).
- `изЛистаИгры(действие)` (game.js:10897) — обёртка «закрыть лист, потом дело».
- `тихоНаКнопку(id, действие)` (game.js:10905) — общая мелкая утилита, вешает
  слушатель, только если узел есть; используется ТОЛЬКО в `подключитьЛистИгры`.
- `подключитьЛистИгры()` (game.js:10910) — вся проводка кнопок листа.
- Ветка в `освежитьКнопкуНастроек(id)` (game.js:10939-10970), которая решает,
  на каких экранах пункт «Настройки» Telegram открывает `открытьЛистИгры`
  (экран-игры, экран-лобби, шаги пути, экран-комнаты, экран-рейтинга-игроков,
  экран-рейтинга).
- Три вызова `закрытьЛистИгры(false)` из чужого кода: `показатьЭкран` (2946),
  `показатьПлашкуИтога` (3012), `спроситьПроВыход` (7561).
- Один вызов `подключитьЛистИгры()` при старте (11350).

Что ОСТАЁТСЯ (не про лист, а про данные, которые лист только показывает —
эти двери передаются в общий модуль как функции, тела не трогаем):
- `переключитьЗвук()` (9090) и участок `показатьСостояниеЗвука()` (9137),
  который пишет в `кнопка-лист-игры-звук`/`лист-игры-звук-состояние»`
  (строки 9157-9160) — сама функция используется ещё и для экрана друга
  и листа витрины, трогать всю функцию нельзя, только убрать 4 строки
  проводки конкретно листа-игры, потому что это возьмёт на себя дверь
  «звук» общего модуля (у него своё «освежитьВидимость», см. п.2).
- `вибрацияДоступна()`, `переключитьВибрацию()`, `показатьСостояниеВибрации()`
  (9173-9226) — то же самое: используются также кнопкой на экране друга,
  трогаем только 2-3 строки внутри `показатьСостояниеВибрации`, которые
  пишут в `кнопка-лист-игры-вибрация`/`лист-игры-вибрация-состояние`.
- `спроситьПроВыход`, `показатьПравила`, `открытьОформление`, `показатьРекорды`,
  `этоЭкранИгры()`, `вернутьсяОткудаПришли()`, `открытьПоверхТекущего()` —
  никаких изменений, эти функции просто передаются как `действие` в двери.

## 2. Мэппинг дверей на формат общего модуля

`window.ЛистЕщё.подключить({ идОткрывающих, экраныСЛистом, двери })`.

```
двери: {
  вМеню: {
    действие: спроситьПроВыход,
    видна: этоЭкранИгры              // готовая функция, ничего не пишем заново
  },
  какИграть: { действие: показатьПравила },
  звук: {
    действие: переключитьЗвук,
    состояние: function () { return звукВключён ? 'вкл' : 'выкл'; }
  },
  вибрация: {
    действие: переключитьВибрацию,
    доступна: вибрацияДоступна,
    состояние: function () {
      return window.Телеграм.вибрацияВключена() ? 'вкл' : 'выкл';
    }
  },
  оформление: { действие: открытьОформление },
  рекорды: { действие: показатьРекорды }
}
```

Важно: `js/лист-ещё.js` УЖЕ поддерживает дверь «вибрация» с полями
`действие/доступна/состояние` (лист-ещё.js:33-35, 79-82, ПОРЯДОК включает
`вибрация` с `idСостояния: 'лист-игры-вибрация-состояние'`) — это сделано
заранее именно под дурака, у шашек эта дверь просто не передаётся
(«своей вибрации у шашек нет», шашки-экран.js:3030-3032). Значит
доработка самого `js/лист-ещё.js` НЕ нужна — только у шашек её нет в
объекте `двери`, у дурака она появится. Менять общий файл в этой задаче
не планируется вообще.

Порядок id в разметке `index.html:1116-1141` уже СОВПАДАЕТ с `ПОРЯДОК`
модуля (меню → правила → звук → вибрация → оформление → рекорды) и с
теми же id (`кнопка-лист-игры-*`, `лист-игры-*-состояние`) — саму разметку
листа менять не нужно, она уже написана «под» общий модуль.

## 3. Витринный лист «Ещё» (id `лист-ещё`) — ВНЕ объёма Э7

Это отдельная, не дублирующаяся сущность: лист витрины сборника (кнопка
«Профиль»/«Звук на всё» — переключает звук ВСЕХ игр разом через
`переключитьЗвукСборника`, index.html:142, game.js:10793-10836). У других
игр (шашки.html, шахматы.html, нарды.html) СВОЕЙ витрины нет — они не
показывают перечень игр, поэтому этого листа у них попросту нет, и
дублирующейся копии, которую можно было бы «увести» в общий модуль, тоже
нет. Задача Э7 описывает именно лист СТОЛА/партии («вторая копия из
game.js» — вторая относительно шашек/нард/шахмат, у которых стол уже на
модуле). Витринный лист план не трогает и не предлагает переводить —
если штаб захочет когда-то унифицировать и его через `window.ЛистЕщё`,
это отдельная задача (он и так однотипный по разметке, но открывается
с других кнопок и с другим набором дверей — «Звук» на весь сборник,
«Рейтинг», без «В меню»/«Как играть»/«Вибрация»/«Оформление»/«Рекорды»).

## 4. Условная видимость «В меню» и списка открывающих кнопок

`видна: этоЭкранИгры` в двери `вМеню` — прямой аналог шашек
(шашки-экран.js:3044-3053), точно воспроизводит нынешнее поведение
(строка 10870-10872 в game.js: видна, только когда `заСтолом`).

Сложнее — `идОткрывающих`. У шашек это список УНИКАЛЬНЫХ id кнопок на
разных экранах. У дурака же 5 из 6 кнопок «⋯» НЕ имеют своего id — это
`<button data-путь="ещё">` без id, по одной на каждом из экранов лобби
(index.html:171), шаг-правила (261), шаг-игроки (291), шаг-настройки (327),
комната (950); только у стола кнопка именная — `кнопка-игра-ещё` (388).
Сейчас `открытьЛистИгры()` (10876-10878) находит нужную через
`document.querySelector('.экран.экран--виден [data-путь="ещё"]')` —
общий модуль такого приёма не знает, ему нужен СПИСОК id
(`найтиОткрывающую()` в лист-ещё.js:148-154 перебирает список и берёт
первую видимую).

Значит понадобится **добавить уникальные id** этим 5 кнопкам в
`index.html` (например `кнопка-лобби-ещё`, `кнопка-путь-правила-ещё`,
`кнопка-путь-игроки-ещё`, `кнопка-путь-настройки-ещё`, `кнопка-комната-ещё` —
по аналогии с шашками, `кнопка-режимы-ещё`/`кнопка-лобби-ещё`) и передать
их все вместе с `кнопка-игра-ещё` в `идОткрывающих`. `data-путь="ещё"`
на кнопках можно оставить (используется путём-раскладкой шагов, не листом) —
это не конфликтует, добавляем id рядом.

`экраныСЛистом` — список id экранов для `освежитьКнопкуНастроек`, ровно
как в нынешней цепочке `if/else if` (10944-10968): `экран-игры`,
`ЭКРАН_ЛОББИ` (`экран-лобби`), три экрана пути (`экран-путь-правила`,
`экран-путь-игроки`, `экран-путь-настройки`), `экран-комнаты`,
`экран-рейтинга-игроков`, `экран-рейтинга`. У двух последних своей кнопки
«⋯» нет вовсе (в разметке нет `data-путь="ещё"` внутри этих секций) —
их НЕ добавляем в `идОткрывающих`, только в `экраныСЛистом` (модуль это
разделяет — ровно так же, как нынешний код: список открывающих кнопок
и список экранов с листом разные вещи).

## 5. Риск для истории браузера (`историяДуракаЖива` и соседи, ~game.js:2848-2913)

Не задевает. `видимыйЭкран()` читает класс `.экран--виден` на секциях —
лист «Ещё» на видимость экранов не влияет вообще (это отдельный плавающий
узел, не `.экран`). `завестиИсториюДурака`/`снятьИсториюДурака`/`popstate`-
обработчик и `шагНазадСоЭкрана` не вызывают ни `открытьЛистИгры`, ни
`закрытьЛистИгры`, ни читают состояние листа. Единственная связь — три
места, которые ЗАКРЫВАЮТ лист при смене экрана (`показатьЭкран`,
`показатьПлашкуИтога`, `спроситьПроВыход`), и это вызовы «через край», их
поведение при переезде на модуль не меняется (см. п.6 — там же способ
сохранить эти три вызова текстуально почти без изменений).

## 6. Риск для тестов, вызывающих старые глобальные имена — и предлагаемое решение

Прямые вызовы `открытьЛистИгры()` / `закрытьЛистИгры(...)` /
`листИгрыОткрыт()` как ГЛОБАЛЬНЫХ функций (не через клик по кнопке) есть
в нескольких tests/-файлах, включая один, что гоняет game.js в vm-песочнице
без браузера (`витрина-по-макету.js`, строки 376: `стр.спросить('закрытьЛистИгры(false)')`).
После переезда на модуль эти функции как отдельные глобальные имена
пропадут (модуль возвращает объект `{ открыть, закрыть, открыт, ... }`,
а не кладёт их в `window`).

**Предлагаю**: не удалять три старых имени, а превратить их в тонкие
обёртки над объектом, который вернёт `window.ЛистЕщё.подключить(...)`:

```js
let листЕщёСтола = null;   // объект { открыть, закрыть, открыт, освежитьКнопкуНастроек }

function открытьЛистИгры() { if (листЕщёСтола) листЕщёСтола.открыть(); }
function закрытьЛистИгры(вернутьФокус) { if (листЕщёСтола) листЕщёСтола.закрыть(вернутьФокус); }
function листИгрыОткрыт() { return Boolean(листЕщёСтола) && листЕщёСтола.открыт(); }
```

Так три существующих вызова (`показатьЭкран`, `показатьПлашкуИтога`,
`спроситьПроВыход`) и `освежитьКнопкуНастроек` не переписываются вообще
(там просто продолжают звать `закрытьЛистИгры(false)`), и БОЛЬШАЯ часть
tests/*.js, которые дёргают эти три имени напрямую, тоже не требует
правки. Это отступление от буквального повтора приёма шашек (там таких
глобальных имён никогда не было), но оно резко уменьшает риск и объём
правки тестов — решение окончательно за штабом при утверждении.

Список файлов tests/, которые упоминают `лист-игры`/`кнопка-лист-игры-*`
и стоит прогнать (или поправить) тем же коммитом — по grep на 17.09.2026:
- `tests/витрина-по-макету.js` — вызывает `закрытьЛистИгры(false)` в vm;
  при сохранении обёрток (см. выше) трогать не должно понадобиться, но
  прогнать обязательно (там же проверка «в лобби Настройки открывают
  именно лист-игры, не лист-ещё» — самое чувствительное место переезда).
- `tests/все-экраны-в-полном-экране.js` — читает `window.открытьЛистИгры`
  как функцию (строка 459) и кликает по `#кнопка-лист-игры-правила`/
  `#кнопка-лист-игры-рекорды`/`#кнопка-лист-игры-закрыть`; с обёртками
  не ломается, прогнать.
- `tests/дорога-к-оформлению.js` — кликает `#кнопка-лист-игры-оформление`,
  не трогает глобальные функции — прогнать.
- `tests/лобби-без-файла-пути.js` — зовёт `закрытьЛистИгры(false)` в
  `evaluate` — с обёртками не ломается, прогнать.
- `tests/лобби-в1.js` — читает классы/фокус узлов листа напрямую (не через
  функции) — устройство модуля (класс «скрыт», фокус на первой видимой
  строке) совпадает, но прогнать обязательно, там же проверка вибрации.
- `tests/новые-кнопки-и-рейтинг.js` — зовёт `закрытьЛистИгры(false)`,
  кликает `#кнопка-лист-игры-вибрация» — прогнать.
- `tests/нутро-стенда.js` — только проверяет наличие id кнопки в разметке —
  прогнать для порядка.
- `tests/сесть-за-стол.js` — кликает `#кнопка-лист-игры-рекорды» напрямую —
  прогнать.
- `tests/стол-по-макету.js` и `tests/стол-правки-ревьюера.js` — зовут
  `открытьЛистИгры()`/`листИгрыОткрыт()` как глобальные функции в
  `evaluate` — с обёртками не ломаются, но это самые прямые потребители
  старых имён, прогнать в первую очередь.
- `tests/кнопки-назад-везде.js` — про дурака напрямую лист не трогает
  (раздел про «В меню» шашек переписан отдельно, коммит 0280876), но
  раз он общий по трём играм и трогает соседние функции возврата —
  прогнать для порядка.

Если штаб решит НЕ оставлять обёртки, а явно перейти на объект
`window.ЛистЕщёСтола` (или подобное публичное имя) — тогда список выше
превращается в список тестов, которые придётся МЕНЯТЬ (не просто
прогонять), это заметно увеличит объём реализации; в плане реализации
это нужно будет прямо разметить как выбранный вариант.
