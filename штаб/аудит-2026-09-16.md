**Как «Важное» ходит по кругу.** Запись рождается в `штаб/важное.json`;
`node штаб/важное.js` проставляет ей время и переписывает раздел «Ждём слова владельца»
в `ЗАДАЧИ.md`; дашборд рисует её кнопками (`штаб/важное-страница.js`); нажатие кнопки
уходит на сервер дашборда POST-запросом, и сервер **пишет файл**
`штаб/ответы.json` (`штаб/дашборд.js`, строка 192 `fs.writeFileSync(ФАЙЛ_ОТВЕТОВ …)`),
письмо словами — в `штаб/письма.json` (строка 220). Ничего исполняемого браузер не
запускает: в шапке `дашборд.js` записано прямо — «Ничего не выполняется по просьбе из
браузера».

**Чем «будят» штаб — ключевой факт.** Штаб сам ставит сторожа инструментом `Monitor`
с таким телом (из лога сессии `52c16fb3`, 15 вызовов за сессию):

```
cd "D:/Claud/Games/штаб"
a=$(stat -c %Y ответы.json); b=$(stat -c %Y письма.json)
while true; do sleep 5
  a2=$(stat -c %Y ответы.json …); …
  if [ "$a2" != "$a" ]; then echo "владелец ответил: изменился штаб/ответы.json"; …
```

То есть сторож — это фоновая команда внутри **той же** сессии штаба. Когда она
срабатывает, продолжается **та же сессия с тем же контекстом**; новая сессия не
стартует. Значит нажатие кнопки на дашборде не «перезапускает штаб», а добавляет ход в
уже раздутый разговор. Это прямо противоречит замыслу «штаб смертен» (см. Р1).

# Приложение. Как пользоваться `штаб/аудит-логи.js`

```
node штаб/аудит-логи.js          окно 7 дней
node штаб/аудит-логи.js 3        окно 3 дня
node штаб/аудит-логи.js 7 3      с 7 дней назад по 3 дня назад (сравнение «до/после»)
```

Что печатает: по каждой сессии штаба — число запросов, максимальный контекст, долю
запросов при контексте больше 300k, модели, длительность, паузы дольше часа, картинки,
вызовы `Agent`; по ролям исполнителей — сессии, запросы, контекст, разбивку инструментов
и долю браузерных; список всех запусков исполнителей с датой, ролью, моделью, именем и
заголовком задания.

Логи читаются построчно потоком (файлы до 100 МБ) и в контекст не попадают.
Роль исполнителя восстанавливается связкой «вызов `Agent` → `agentId` из его
tool_result → файл `agent-<id>.jsonl`»; у исполнителей, запущенных до начала окна,
роль печатается как `?`.
