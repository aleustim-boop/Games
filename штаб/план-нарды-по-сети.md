# План «Нарды по сети» — играть в нарды с другом онлайн

Просьба владельца 22.09 22:22: «добавь возможность играть в нарды онлайн». Важность: **скоро**.
Опись и план написал исполнитель (Plan) 22.09 22:35, штаб утвердил 22:37 с пометками «Решения штаба» внизу.

## 1. Опись

### Что уже есть и работает на нас

**Правила нард написаны под сервер — это главная удача.** `js/нарды-правила.js` (1714 строк):
- `бросить(партия, кубики)` — кубики приходят снаружи; если не передали, берётся `Math.random` (сервер обязан передавать свои);
- `сделатьХод(партия, { шаги })` — ход целиком, каждое перемещение переспрашивается у `возможныеШаги`, недоигранный ход → `null`, доска не тронута. Это и есть «клиенту не верим» на готовой полке;
- пустой список шагов — законный «пропуск» (когда ходить нечем);
- `итог(партия)` уже даёт `{ победитель, цена (1/2/3), видПобеды ('обычная'/'марс'/'кокс'), причина }`;
- ни одного обращения к документу; `module.exports` для Node уже есть; самопроверка `node js/нарды-правила.js` — **75 проверок, плохих 0**, в ней 1000 длинных партий за 8,1 с (проверка одного хода на сервере стоит доли миллисекунды);
- виды правил: `КОРОТКИЕ`/`ДЛИННЫЕ`, выбираются через `создатьПартию({ вид, первый })`.

**Образец сетевой игры без карт** — `server/игры/шашки.js` (625 строк): перевод «место за столом ↔ цвет», ручная сборка `видДляИгрока` поле за полем, сдача и ничья как отдельные действия той же двери `/ход`, ход бота через ту же проверку. Мост `js/шашки-сеть.js` (180 строк) — маленький и полностью копируемый по устройству.

**Включится само, если игра встанет в реестр:** комнаты, коды, приглашения-ссылки, возврат за стол, уборщик, реванш, знакомства; рейтинг (`server/рейтинг.js` открывает таблицу по имени игры, `нарды: { вес: 0.3 }` в `server/игры/умолчания.js` уже стоит; `server/комнаты.js:2306` считает партию по полям `завершена/результат/проигравшие` — тем же, что заполняет шашечный файл).

**Не включится само (проверено):**
- **подбор соперника** — в `server/сервер.js:2524` игра зашита словом `'дурак'`; у шашек подбора тоже нет. Полка очереди (`server/подбор.js:65`) игру в ключе учитывает, но браузер её не шлёт. Отдельный поздний этап;
- **билеты за игру с ботом** (`server/билеты.js:61`) выдаются только дураку — нарды с ботом в рейтинг не идут. Совпадает с подписью макета «Тренировка не влияет на рейтинг», ничего делать не надо;
- **сетевых экранов на странице нард нет вовсе**: в `нарды.html` есть `экран-лобби`, `экран-режимов`, `экран-бота-нард`, `экран-игры`, `экран-итога`, `экран-как-играть`, `экран-оформления`. Нет `экран-друга`, `экран-комнаты`, `экран-входа`, нет узла `строка-связи`. У шашек они есть и оформление для них в общем `style.css` уже описано — разметка копируется, файлы оформителя не трогаются;
- **у экрана нард нет сетевого режима**: `window.НардыЭкран` отдаёт наружу только `показатьЧужойХод`, `откатитьХодЦеликом`, `текстПлашкиХода`. Нет ни `включитьСеть`, ни `показатьСетевойВид`, ни двери «покажи такой-то экран» (у шашек это отдельный `js/шашки-режимы.js`);
- **в правилах нет пары «снимок партии → партия»**. У шашек это `картинкаПартии`/`партияИзКартинки`, ими и ездит доска по сети. Нардам такую пару надо завести — единственная правка самого файла правил.

### Что нужно нового
1. В `js/нарды-правила.js` — снимок партии и восстановление из него (общий файл: и сервер, и браузер).
2. `server/игры/нарды.js` — новый файл по образцу шашечного.
3. Одна строка в `server/игры/реестр.js` и ~6 строк в `server/комнаты.js` (вариант нард как настройка стола).
4. Сетевой режим в `js/нарды-экран.js` (приём вида + отправка броска и хода).
5. Новый мост `js/нарды-сеть.js` и одна строка в `js/сеть.js` (`МЕТКИ_ИГР`).
6. Сетевые экраны в `нарды.html` + включение карточки «Онлайн» в `js/нарды-лобби.js`.

## 2. План по этапам

Каждый этап — 1–2 файла, до пары часов. Ревьюер обязателен везде, где сервер, сеть или общий файл.

**Э1. Снимок партии в правилах** (самый безопасный, сеть не трогается).
Файлы: `js/нарды-правила.js`, новая `tests/нарды-снимок-партии.js`. Роль: developer полная, reviewer.
Добавить `картинкаПартии(партия)` и `партияИзКартинки(картинка)` — снимок со всеми полями хода (вид, ходит, пункты с именами шашек, бар, вне, бросок, кубики, сыграно, сГоловы, лимитГоловы, максимумКубиков, обязательныйКубик, ходов, завершена и итог). Имена шашек (`б1…б15`, `ч1…ч15`) обязаны сохраняться: узел шашки на экране живёт всю партию, и подмена имени превратит ход в скачок.
Проверка: гоняет 300 случайных партий, после каждого хода снимок → восстановление → сравнение `отпечатокПозиции` и списка `возможныеШаги`. Краснеет на настоящей поломке: в копии правил (во временной папке исполнителя) из снимка убирается поле `кубики` — восстановленная партия разрешает ходить заново, списки шагов расходятся.

**Э2. Нарды для сервера, без реестра.**
Файлы: новый `server/игры/нарды.js`, новая `tests/нарды-сервер-правила.js`. Роль: developer полная, reviewer обязателен.
Договор игры для сервера целиком (см. `server/игры/реестр.js`). Кубики бросает сервер. Действия двери `/ход`: `бросить`, `ход` (список перемещений целиком), `сдаться`. Ход проверяется `Правила.сделатьХод` — присланному не верим никогда. `видДляИгрока` собирается вручную, поле за полем. В реестр пока НЕ вписываем — боевой сервер этим этапом не меняется вовсе.
Проверка: зовёт модуль напрямую, без сети: раздаёт, играет две партии до победы (короткие и длинные), пробует ход не в свою очередь, чужой шашкой, второй бросок подряд, ход из другой позиции, пустой ход при живых шагах. Краснеет: в копии файла `сделатьХод` начинает верить присланным шагам — проверка «чужой шашкой» проходит, значит краснеет.

**Э4. Экран нард принимает вид сервера.**
Файлы: `js/нарды-экран.js`. Роль: developer полная, tester.
`включитьСеть(отправитель)`, `выключитьСеть()`, `показатьСетевойВид(вид)`: доска берётся из снимка сервера как единственная правда, чужой ход проигрывается по шагам существующей `проигратьШаги` темпом `ТЕМП_ЧУЖОЙ` (отдельной ветки показа не заводить — она уже три недели молча не работала в шашках).
Проверка (браузерная, одно окно, поддельный вид): пришёл вид с чужим ходом — шашки доехали, доска совпала со снимком.

**Э5. Экран нард отправляет бросок и ход.**
Файлы: `js/нарды-экран.js` (тот же файл — строго после Э4, один файл один исполнитель). Роль: developer полная, tester.
Кнопка «Бросить кубики» в сетевом режиме шлёт `{действие:'бросить'}`; «Подтвердить» шлёт весь ход — `партия.сыграно` списком `{откуда, куда, кубик}`; «Отменить ход» работает только до отправки; отказ сервера показывается словами и позиция возвращается к присланной.
**Почему ход уходит целиком, а не по одному перемещению:** правила умеют принимать только доигранный ход (`сделатьХод` отвергает недоигранный), иначе серверу пришлось бы хранить полуход и уметь его откатывать; при дубле это четыре обращения вместо одного и четыре рассылки сопернику; «Отменить ход» на экране уже отменяет ход целиком, и при отправке по шагам его пришлось бы отнимать у человека. Единственная плата — соперник ничего не видит, пока вы думаете; она уже принята в шашках.

Ни одного нового правила оформления: все классы уже есть в общем `style.css`.
Проверка: `tests/дорога-до-каждой-игры.js` и новая строка в проверке лобби — каждый названный id найден на странице; ноль найденного считается провалом.

**Э7. Мост в сеть и метка игры.** **Перезапуск сервера — штаб.**

## 3. Договор имён

Чтобы исполнители разных этапов не разошлись.

**Слово игры:** везде `нарды`; латиницей в ссылке — `nardy` (так же, как ключи памяти `nardy_version`).

**Снимок партии (Э1):** `Правила.картинкаПартии(партия)` → `Правила.партияИзКартинки(картинка)`. Внутри снимка поля называются ровно как в партии: `вид, ходит, пункты, бар, вне, бросок, кубики, сыграно, сГоловы, лимитГоловы, максимумКубиков, обязательныйКубик, ходов, завершена, победитель, цена, видПобеды, причина`.

**Настройка стола:** `вариантНард` со значением `'короткие'` или `'длинные'` (слово «вид» занято видом для игрока — не путать). Поле необязательное, не пришло — короткие.

**Действия двери `/ход`:** `'бросить'`, `'ход'` (`{ шаги: [{ откуда, куда, кубик }] }`, пустой список = пропуск), `'сдаться'`. Ничьей по соглашению в нардах не делаем.

**Слова событий (`видСобытия`):** `'бросок'`, `'ход'`, `'пропуск'`, `'сдался'` плюс общие `'вошёл'`, `'ушёл'`, `'пропал'`.

**Поля вида для игрока** (собираются вручную в `server/игры/нарды.js`): `игра`, `вариант`, `доска` (снимок), `мойЦвет`, `чейХод`, `яХожу`, `бросок` (`[а,б]` или null), `кубикиОсталось`, `максимумКубиков`, `обязательныйКубик`, `ходитьНечем`, `последнийХод` (`{ чей, мой, шаги, запись }`), `итог` (`{ победитель, цена, видПобеды, причина, яВыиграл }`), `креслоСоперника`, `завершена` — плюс общие поля стола ровно теми же именами, что у шашек.

**Двери браузера:** `window.НардыСеть = { идёт, покинуть }`; `window.ИграПоСети = { начать, показатьВид, показатьСвязь, экран, вМеню, идёт }`; к `window.НардыЭкран` добавляются `включитьСеть`, `выключитьСеть`, `показатьСетевойВид`, `показатьПоИмени` (перевод дураковых имён экранов: `экран-меню` → `экран-лобби`, `экран-игры` остаётся `экран-игры`).

**Id разметки** (Э6) — копируются из `шашки.html` без единого переименования; свои только `строка-связи` (имя то же) и карточка `лобби-онлайн`.
