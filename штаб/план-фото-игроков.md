## Главное

## Где сейчас фото нет и почему

**1. Как сервер узнаёт имя игрока (фото шло бы тем же путём, но его нет)**

- Браузер берёт подпись: `js/сеть.js:3047-3054` — `подписьTelegram()` читает `window.Telegram.WebApp.initData`
  целиком (строка, подписанная Telegram).
- Кладёт `initData: подпись` в тело каждого POST — `js/сеть.js:4882` (билет), `:4964`, `:5017`/`:5150`.
- Сервер проверяет подпись HMAC-ом токена бота: `server/сервер.js:969-1009` (`ктоПрислал` → `ктоПодписал`).
- Имя достаёт `имяИзПодписи(initData)`, `server/сервер.js:2867-2875` — берёт `first_name || username`.
  **`photo_url` там не читается вообще.**
- Хранит: `server/рейтинг.js`, `пустаяЗапись()` строки 254-270: `{ номер, имя, очки, побед, ничьих, партий,
  деньБотов, очкиОтБотовЗаДень }`. Поля «фото» нет.
- Отдаёт: `server/рейтинг.js:931-949` — `строка(запись, место, этоЯ, ...)` вручную собирает
  `{ место, имя, очки, побед, партий, этоЯ, движение?, сдвиг? }`. Номер не уходит никогда. Поле `фото`
  придётся добавить именно сюда, руками.

**2. Придёт ли `photo_url` от Telegram**

Клиент уже умеет читать это поле — `js/telegram.js:153-164`, `фотоИгрока()`, белый список знаков адреса
(строка 152), наружу `window.Телеграм.фотоИгрока` (`:3944-3946`). Но это только про СВОЙ аккаунт, и
Telegram кладёт `photo_url` в `initDataUnsafe.user` только для мини-аппов, открытых из Attachment Menu.
Наша игра открывается inline-кнопкой «Играть» (`bot/бот.js:491-492`) и кнопкой меню чата (`:510-514`);
регистрации в Attachment Menu нет. **Вывод: при нынешнем запуске `photo_url` почти никогда не придёт** —
ни для чужих (Telegram чужие фото мини-аппу не даёт вовсе — комментарий `js/рейтинг-экран.js:1153-1155`),
ни для своего в большинстве случаев.

**3. Запасной путь — Bot API**

`bot/бот.js` и `server/сервер.js` — разные процессы (бот ходит на сервер по HTTP). Но сервер уже читает
`bot/.env` сам — `server/сервер.js:171-177` — и держит `ТОКЕН_БОТА` в памяти (`:872-891`); сервер уже умеет
ходить на `api.telegram.org` (`:1047`). Значит фото можно тянуть прямо из `server/`, отдельным маленьким
модулем (`getUserProfilePhotos` + `getFile` + скачивание), бот не трогая.

**Безопасность:** Telegram отдаёт файл по адресу `https://api.telegram.org/file/bot<ТОКЕН>/<path>` — этот
адрес **нельзя** класть в ответ `/рейтинг` (токен уедет в браузер). Сервер сам скачивает байты и отдаёт файл
со своего адреса (`GET /фото/<номер>.jpg`), кэш на диске `server/данные/фото/<номер>.jpg` приёмом
«временный файл + переименование» (`рейтинг.js:138-139`, `файлМест()` `:146-147`), обновление раз в
сутки, папка вне git (как весь `server/данные`).

**Скорость:** `/рейтинг` обязан отвечать быстро. В `строка()` — только синхронная проверка файла на диске
(есть/нет, не устарел ли); поход в Telegram API — отдельно, фоном, по образцу «снимка вчерашних мест»
(`рейтинг.js:107-118`, `обновитьСнимокЕслиНужно()`).

**4. Клиент: как рисовать**

`js/рейтинг-экран.js`: `инициалы()` (:1161-1166), `узелИнициалов()` (:1174-1181); `поставитьФото(строка)`
(:1257-1287) грузит адрес через `new Image()`, ставит `--фото-аватара` и класс `рейтинг-строка--фото`
только в `onload`; в `onerror` инициалы остаются. Зовётся только для своей строки (`:1300`, `:1559`).
CSS уже готов и под таблицу, и под подиум: `style.css:12331-12396`, `12594-12702`. Работы по CSS почти нет.
Нужно: брать адрес из поля `данные.фото` от сервера и звать для каждой строки, у которой оно есть;
своё клиентское фото — приоритетнее.

**5. Приватность**

Игрок может закрыть фото в настройках Telegram — тогда `getUserProfilePhotos` вернёт `total_count: 0`,
поля `фото` в ответе не будет, клиент честно остаётся на инициалах. Это не брак.
