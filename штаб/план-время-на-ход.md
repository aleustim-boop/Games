# План: время на ход (дурак)

Задача из очереди: «Время на ход: 30 / 60 секунд или без таймера» — второе
из недостающего по ответу владельца «да» (10 сентября). Первое (онлайн-
подбор) сделано и опубликовано 17 сентября.

Опись сделал developer (17.09, без кода, только чтение). План утверждён
штабом в тот же день. Ниже — итоговый план с решениями штаба по вопросам
разработчика.

## Что уже есть (важно, чтобы не задваивать)

- Правил дурака отдельным файлом нет — весь движок живёт в `js/game.js`
  (раздача, ход, атака/защита/подкид, `ходБота`, `объявитьБеру`, `пас`,
  `завершитьПодход`), сервер требует именно его через
  `server/партия-по-сети.js` (сам без правил) и `server/игры/дурак.js`
  (договорная обёртка, тоже без правил). Правило «время вышло» пишем
  **один раз в js/game.js** — раздвоения не будет.
- Строка «Вы» — `#строка-меня` в index.html (пилюля `#статус-хода`),
  строка соперника — `#рука-бота`, обе рисует js/game.js. Похожего
  таймера в проекте нет ни у одной игры — заводим первый раз, по эталону
  владельца (`эталон-вида.md`, раздел 3б, пп. 3 и 5: пилюля со значком
  часов в обеих строках, у активного — салатовая обводка/заливка).
- В `js/дурак-путь.js` уже есть заготовка: `ВАРИАНТЫ_ВРЕМЕНИ` (30/60
  помечены `скоро: true`), `выбратьВремя(секунд)` (сейчас отказ,
  `ПРИЧИНА_ТАЙМЕРА`), шаг 3 «Настройки» в index.html (`путь-время`).
  Снимаем пометку «скоро», заводим `выбор.время`.
- Сервер не тикает по всем комнатам разом — только `уборщик` каждые N
  секунд. Готовый образец точного таймера на комнату — `таймерБота`
  (server/комнаты.js). Просрочку хода делаем тем же приёмом (свой
  `setTimeout`), не ленивой проверкой при опросе — иначе просрочка
  сработает с опозданием на длину поллинга.

## Решения штаба по вопросам разработчика

1. **Таймер-пилюля — в обеих строках** («Вы» и соперник), не только
   «Вы» — по эталону владельца. Очередь.md сузила формулировку словами
   владельца из более ранней просьбы, но раз есть готовый эталон вида —
   дешевле сделать по нему сразу, чем переделывать потом.
2. **Просрочка первого хода подхода атакующим** (стол пуст, «Бито»/
   «Взять» ещё не доступны, ничего не сделать безопасно нельзя) —
   звать существующую дверь `ходБота` (простой уровень) за игрока, как
   если бы за него сходил лёгкий бот. Это последовательно с двумя
   другими случаями просрочки (защищающийся просрочил → «Взять»,
   атакующий после первой карты → «Бито») — везде правило одно:
   просрочка = автоматика решает вместо человека, не зависание партии.
3. **Онлайн-подбор таймер пока не учитывает** — ключ полки подбора
   (`дурак|мест2|переводной:да/нет`, server/подбор.js) не трогаем и не
   расширяем. Подбор всегда сводит без таймера («без таймера» — таким,
   каким уже опубликован), пока владелец не попросит иначе. Причина:
   не плодить узкие полки на пока небольшой аудитории подбора, не
   трогать уже принятый и опубликованный модуль сверх необходимости.

## Устройство (по описи developer)

- `js/game.js`: новая функция(и) «ход по просрочке» — три случая решения 2
  выше; поля партии — лимит секунд на ход и метка начала текущего хода
  (заводит `создатьПартию`/переход хода). Локальная игра с ботами сама
  заводит интервал на клиенте и по истечении зовёт то же правило прямо
  (раздваивается только «кто и когда включает таймер», не сама логика).
- `server/партия-по-сети.js`: лимит берётся из настроек стола; в
  `видДляИгрока` — новое поле, **уже пересчитанный остаток секунд** на
  момент ответа (не абсолютное время сервера) — клиент только рисует
  пилюлю, решений не принимает (правило «клиенту не верим»).
- `server/игры/дурак.js`: дверь просрочки в договоре «игра для сервера»,
  если нужна (решает developer на Э2 по факту).
- `server/комнаты.js`: свой `setTimeout` на просрочку хода в комнате, по
  образцу `таймерБота`; рассылка нового вида игрокам по срабатыванию.
- `js/дурак-путь.js`: снять «скоро» у 30/60, `выбор.время`, новый ключ
  памяти `КЛЮЧИ_ПАМЯТИ.времяНаХод` → латиницей `move_timer_durak`,
  значение строкой (`'0'`/`'30'`/`'60'`); прокинуть в `настройкиПартии()`
  (боты) и `столДляКомнаты()` (друг). Переезда со старого ключа не
  требуется — ключ совсем новый.
- `index.html` + `js/game.js` (рисование): узлы пилюли-таймера в обеих
  строках, стиль по образцу уже готовой `#статус-хода`. Не новый экран
  (существующий стол) — designer не звать, косметику делает developer.
  Разметка и её JS — одним коммитом.

## Риски (обязателен reviewer)

- `js/game.js` — самый большой общий файл правил; новое правило
  просрочки — ревью обязательно («правила игр не раздваиваются»).
- `server/комнаты.js` — самый рискованный общий файл (270 КБ, ошибка
  роняет живые партии при перезапуске); `node -e "require('./комнаты.js')"`
  из `server/` до сдачи, и reviewer обязателен, как и на подборе.
- `server/партия-по-сети.js` — новое поле в `видДляИгрока`: ревью на
  утечку (не абсолютное серверное время, не лишние поля).
- Боевой сервер комнат — порт 8790, не перезапускать; тестовые копии —
  другой порт, гасить по PID.
