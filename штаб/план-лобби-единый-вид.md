# План: единый вид лобби во всех играх (дурак, шахматы, шашки, нарды)

Задача владельца: «все пункты меню должны иметь один вид в лобби во всех играх, играть онлайн, и так далее».
Референс — архив `lobby-ui-pack` (структура экранов, палитру НЕ берём — красим в нашу салатовую тему по
`эталон-вида.md`, решение владельца уже принято).

## 1. Что реально прочитано

- `эталон-вида.md` целиком — палитра, отступы, карточки, правило «настроек мало — всё в лобби одним
  экраном; много (дурак) — три шага».
- Пакет-референс: `README.md`, `manifest.csv`, `shared/style_tokens.json`.
- Секции `#экран-лобби` в `index.html` (дурак), `шахматы.html`, `шашки.html`, `нарды.html` — целиком.
- CSS-классы в `style.css`: `.карточка-входа*`, `.лобби__*`, `.карточка-профиля*`, `.переключатель*`,
  `.верх-игры__кнопка`, стили disabled-состояния «онлайн».
- `js/нижние-вкладки.js` — как устроена вкладка «Рейтинг» (отдельный экран, не блок лобби).

## 2. Расхождения между 4 лобби — что намеренно, а что нет

**Намеренные расхождения (не трогаем, задокументированы в коде/CLAUDE.md):**
- У дурака нет переключателей «Вариант / Сложность бота / Время на ход» прямо в лобби — они вынесены в
  3-шаговый путь (`#экран-путь-правила/-игроки/-настройки`), потому что настроек много (правила, 2–6
  игроков, рассадка, колода, время на ход, сложность). У шахмат/шашек/нард настроек мало — переключатели
  прямо в лобби. Это ровно правило CLAUDE.md «настроек мало — всё в лобби одним экраном; много (дурак) —
  три шага». Не унифицирую.
- Карточка профиля показывает разное: у дурака — место в общем рейтинге, у шахмат/шашек — серия побед
  подряд, у нард — «Мой счёт» без числа. Причина прямо в комментариях: у дурака есть общий рейтинг за
  билеты, у шашек/шахмат его нет (но есть честная серия побед), у нард нет модуля рекордов вовсе.
  Не унифицирую — выдумывать цифры, которых нет, нельзя.
- Набор входов по сетевому функционалу разный: у дурака — «Найти игру» (открытые столы) + «Играть
  онлайн» (случайный соперник, оба рабочие); у шашек — «Играть с другом онлайн» (по коду/ссылке, рабочее)
  + «Найти игру» (открытые столы, рабочее), но НЕТ случайного подбора; у шахмат и нард сети вовсе нет
  (только «Вдвоём на этом устройстве», «Играть онлайн» — заглушка disabled+«скоро»). Это разный прогресс
  фичи по играм (сервер комнат отдаёт разное), не баг вида — план вида это не чинит, только выравнивает
  ФОРМУЛИРОВКИ и ПОРЯДОК того, что уже есть.
- Отсутствие `<figcaption>` под картинкой у шахмат/шашек/нард (у дурака есть) — в коде явно написано
  «подписи-текста поверх картинки нет нарочно», баннеры этих игр — другая пропорция и фото, текст
  забивал бы фигуры/доску. Не трогаю.
- «Раздача дня» и «Пригласить друзей» — только у дурака (ежедневная раздача — уникальная фича, приглашение
  друзей пока сделано только там). Не унифицирую наличие, эти пункты не переносятся другим играм в этом
  плане (это не про вид, а про новый функционал — вне задачи).

**Реальные несоответствия вида/разметки без видимой причины — их и предлагаю выправить:**
1. `шашки.html`: карточка «Найти игру» (список открытых столов) и карточка «Вдвоём на этом устройстве»
   используют ОДИН И ТОТ ЖЕ модификатор класса `карточка-входа--вдвоём`, хотя это две разные по смыслу
   карточки. У дурака для «Найти игру» используется отдельный класс `карточка-входа--онлайн`, который
   у шашек сейчас свободен (там `--онлайн` не занят никем). Предлагаю у шашек тоже отдать
   `карточка-входа--онлайн` под «Найти игру», а `--вдвоём` оставить только за «Вдвоём на этом устройстве».
2. Разнобой в названии одной и той же функции «играть с другом по коду/ссылке»: у шашек — «Играть с
   другом онлайн», нигде больше такого текста нет. Предлагаю единое название «Играть с другом» (подпись
   уже есть — «По коду или ссылке»), без слова «онлайн» в названии (оно и так про сеть).
3. `index.html` (дурак): карточка «Пригласить друзей» — единственная во всех 4 играх, где нет
   `карточка-входа__подпись` (только название, без второй строки серым). У всех остальных карточек входа
   во всех играх подпись есть всегда. Предлагаю добавить короткую подпись (текст — на усмотрение штаба/
   владельца, например «Позовите компанию»).
4. `index.html` (дурак): единственное лобби без подписи-девиза под H1 (`<p class="подпись">…</p>`) —
   у шахмат и шашек «Классическая игра для двоих», у нард то же. У дурака после `<h1>` сразу идёт карточка
   профиля. Предлагаю добавить короткую подпись под H1 дурака для единообразия шапки экрана (текст —
   решение штаба/владельца, например «Народная игра для компании»).

Блок рейтинга внутри самого лобби (как отдельная секция на экране) — **не добавляю**: у нас рейтинг уже
вынесен в отдельную вкладку нижней панели («Рейтинг» → `js/рейтинг-экран.js`), это совпадает с тем, что
и в референс-пакете `rating_screen` — отдельный полноэкранный экран, а не блок внутри лобби. Менять не
нужно, архитектура уже правильная.

## 3. Единый набор пунктов меню лобби (порядок и названия)

Предлагаемый общий порядок карточек-входа (сверху вниз), с оговоркой «пункта нет — карточки нет вовсе
или честно disabled+«скоро», а не подделка):

1. **Найти игру** (`--онлайн`) — список открытых столов, где эта функция уже реализована (дурак, шашки).
2. **Играть онлайн** (`--играть-онлайн`/базовый тёмный вид) — случайный соперник, где реализовано (дурак).
   У шахмат/нард — как сейчас, disabled + «скоро».
3. **Играть с ботом** (`--боты`, акцентная салатовая) — главная кнопка, уже одинакова во всех 4 играх,
   не трогаю.
4. **Играть с другом** (`--друзья`) — по коду/ссылке, где реализовано (шашки; переименовать по п.2 из
   раздела 2).
5. **Вдвоём на этом устройстве** (`--вдвоём`) — где есть (шахматы, шашки, нарды).
6. Нижняя тихая строка **«Есть код? Войти»** — где есть (дурак, шашки).
7. Особые пункты конкретной игры (Раздача дня, Пригласить друзей у дурака) — в конце списка, как сейчас.

Фактическая перестановка карточек внутри файла — где текущий порядок уже совпадает с этим списком,
трогать не нужно (проверил: дурак и шашки уже примерно в этом порядке; у шахмат и нард порядок
короче и тоже совпадает). Основная работа — не перестановка, а три точечные правки из раздела 2.

## 4. Что чисто CSS/разметка (developer), что требует нового экрана (designer)

Всё из раздела 2 — **только текст и один class-swap в существующих 4 html-файлах**, ничего нового не
рисуется, новых узлов/состояний нет. Роль — **developer**, designer не нужен ни на одном шаге.

Правки в `style.css` не ожидаются: используются уже существующие классы `карточка-входа--онлайн` (стиль
уже описан, применяется к «Найти игру» у дурака) и `карточка-входа--вдвоём` (стиль уже описан). Если
по факту правки понадобится точечно поправить `.карточка-входа--вдвоём` (сейчас завязан на «Найти игру»
у шашек — вдруг там что-то специфичное в CSS под конкретный текст), это выяснится на шаге и будет
отдельной строкой отчёта, не отдельным этапом.

Что НЕ входит в этот план (требует нового экрана/узла или решения владельца, не делаю молча):
- Promo/quote-баннер внизу лобби (`quote_banner.png` из референса) — у нас такого блока нет ни у одной
  игры. Это НОВЫЙ элемент — не добавляю, только сообщаю: если владелец хочет его — отдельная задача с
  designer.
- Списки открытых комнат (`room_card`, `filters_bar` из референса) — у нас это уже отдельный модуль
  `js/открытые-столы.js`, не входит в 4 файла лобби из этого задания. Если требуется его тоже привести
  к единому виду — отдельный план, отдельный файл, спросить штаб отдельно.
- Тексты новых подписей (п.3–4 раздела 2) — предлагаю черновой вариант, но финальный текст лучше
  утвердит штаб/владелец при приёмке.

## 5. Этапы

**Э1 — developer, `index.html`.**
Добавить подпись под H1 (девиз дурака) и подпись у карточки «Пригласить друзей». 2 короткие правки текста.
Проверка: открыть index.html в браузере, посмотреть лобби дурака, сверить с шахматы.html/шашки.html —
структура шапки и карточек совпадает.

**Э2 — developer, `шашки.html`.**
Переименовать «Играть с другом онлайн» → «Играть с другом»; поменять класс карточки «Найти игру» с
`карточка-входа--вдвоём` на `карточка-входа--онлайн`. 2 точечные правки.
Проверка: открыть шашки.html в браузере, убедиться что обе карточки визуально не слиплись (разные
модификаторы у «Найти игру» и «Вдвоём»), клики по-прежнему работают (id кнопок не менялись).

**Э3 — tester (если требуется штабом).**
Открыть все 4 лобби (index.html, шахматы.html, шашки.html, нарды.html) в браузере/скриптом, убедиться,
что после правок консоль чистая, кнопки нажимаются (id не менялись — риска для памяти игрока нет),
скриншот на память смотрителю не нужен — новых экранов не появилось.

**Э4 — reviewer (по правилу «звать на рисковое место — сеть»).**
`шашки.html` завязан на сетевой функционал (кнопки входа слушает `js/сеть.js`/`js/открытые-столы.js`,
трогать эти файлы нельзя). Правки в Э2 не трогают id и логику, только текст/class, но раз файл рядом
с сетью — стоит позвать ревьюера подтвердить, что class-swap не задел селекторы в JS (js ищет узлы
по id, не по классу `--вдвоём`/`--онлайн` — проверить явно).

Итого 2 коротких этапа для developer + 1 tester + 1 reviewer на риске. Оба developer-этапа — по одному
файлу, можно делать последовательно одним исполнителем или параллельно двумя (файлы разные, не пересекаются).

## 6. Риски

- **`style.css` и `js/game.js` сейчас уже изменены** (`git status`: `M style.css`, `M js/game.js`) —
  судя по последним коммитам («Время на ход, Э4: варианты 30/60 сек в js/дурак-путь.js») идёт параллельный
  этап про пилюли-таймеры хода. Этот план **style.css не трогает вовсе** (Э1–Э2 — только html), поэтому
  пересечения с параллельной работой над таймерами нет. Если в Э2 всё же понадобится CSS-правка (см.
  раздел 4, «если по факту»), её нужно делать только в секциях `.карточка-входа*`/`.лобби__*`, не рядом
  с узлами таймеров/пилюль партии — штабу стоит на всякий случай уточнить, какие именно строки style.css
  сейчас держит исполнитель «Время на ход, Э5», прежде чем разрешать мне трогать style.css.
- **`index.html` тоже отмечен изменённым** в git status до старта этого плана — не знаю, чья это правка
  (может быть моя старая недосданная, может чужая). Перед Э1 стоит уточнить у штаба, не пересекается ли
  текущий diff в index.html с секцией `#экран-лобби`, чтобы не наложить правки поверх чужих.
- **Память игрока (localStorage/CloudStorage)**: план не переименовывает и не трогает ни одного `id` —
  меняются только видимый текст и один CSS-класс. Ключи памяти (`chess_bot_level`, `nardy_version` и
  т.п.) через id/атрибуты не завязаны на эти правки — риска потерять сохранённые настройки нет.
- Оба этапа — точечные правки на 1 файл, роль **developer**, designer не привлекается (нет новых экранов).
