# План: онлайн-подбор соперников (дурак)

Задача из очереди: «Онлайн-подбор соперников: „Играть онлайн“, если никого
за 20 секунд — бот». Первое из недостающего по ответу владельца «да»
(10 сентября): онлайн-подбор → время на ход → фильтры рейтинга. Берём
только онлайн-подбор.

Опись сделал developer (17.09, без кода, только чтение). План утверждён
штабом в тот же день. Ниже — итоговый план с решениями штаба по открытым
вопросам.

## Что уже есть (важно, чтобы не задваивать)

- Боты живут **на сервере** (`server/комнаты.js`: `новыйБот`, `таймерБота`,
  `ходЗаБота`). Клиентскую логику бота звать не нужно.
- Половина инфраструктуры подбора уже написана: `/открытые-столы` и
  `/сесть` (`server/сервер.js` ~1947–2054), `комнаты.открытыеСтолы`,
  `столОткрытДляПосадки`, клиент `Сеть.открытыеСтолы/сестьЗаСтол`,
  экран `js/открытые-столы.js`. Это **другая, не связанная функция**
  (ручной выбор чужого открытого стола) — не трогаем, не путаем с задачей.
- Стол на двоих стартует сам: `войтиВКомнату` (комнаты.js:1153) раздаёт
  карты без кнопки «Начать», когда стол не «компания». Сведение двоих =
  `создатьКомнату` + `войтиВКомнату`.
- **Карточка «Играть онлайн» уже нарисована и ждёт именно эту задачу** —
  `js/дурак-путь.js`: `ТЕКСТЫ_ЛОББИ.онлайн` (строка 71, подпись «Соперники
  со всего мира», пометка «скоро»), но режим `онлайн` не входит в `РЕЖИМЫ`
  (строки 58-61) и заворачивается отказом `ПРИЧИНА_ОНЛАЙН` (строка 62, 348:
  `если режим === 'онлайн' return отказ(ПРИЧИНА_ОНЛАЙН)`). **Новую карточку
  в index.html создавать не нужно** — index.html и карточка «Найти игру»
  (id `лобби-онлайн`, открытые столы) этой задачи не касаются.
- Рейтинг правил не различает подкидной/переводной — подбор «по правилам»
  = совпадение настроек стола, не рейтинговых фильтров (те третьей задачей).

## Решения штаба по вопросам разработчика

1. **Где кнопка** — см. выше, `js/дурак-путь.js`, режим `онлайн`. Убрать
   `ПРИЧИНА_ОНЛАЙН`-отказ, завести на новый механизм подбора. index.html
   не трогаем.
2. **Объём подбора** — только 1×1, правила (подкидной/переводной) берутся
   из памяти игрока (`КЛЮЧИ_ПАМЯТИ.переводной`), без выбора числа мест.
   «Парами» (4 игрока) в автоподбор пока не включаем.
3. **Уровень подсаженного бота** — «обычный» (`СЛОЖНОСТЬ_БОТОВ.обычный`).
4. **Designer** — не звать. Экран ожидания собирается общими классами по
   образцу `js/открытые-столы.js`. Смотритель оценит снимок при сдаче Э4.

## Устройство (по описи developer)

- Новый файл `server/подбор.js`: очередь ждущих, `Map` «полка → список»,
  ключ полки = `дурак|мест2|переводной:да/нет`. Запись ждущего:
  `{ номерТелеграм, имя, метка, ключОжидания, всталВ, доБота=+20с,
  состояние, код, пропуск }`. Один номер Telegram — одна запись. Уборка
  зависших записей по сроку + потолок записей. Комната создаётся только
  в момент сведения. Модуль знает только `комнаты.создатьКомнату /
  войтиВКомнату / показатьИгроку`, HTTP не знает.
- `server/комнаты.js`: одна новая функция `посадитьБотаОтПодбора(код,
  уровень)` — сажает бота на свободное место без включения «компании»
  (иначе игрок увидит прихожую с кнопкой «Начать» вместо стола).
- `server/сервер.js`: три двери — `POST /подбор`, `POST /подбор-новости`
  (длинный опрос, как `/что-нового`), `POST /подбор-отмена`. Личность —
  только из подписи Telegram. Ответы собираются вручную полем за полем
  через `комнаты.показатьИгроку` — новых полей в `видДляИгрока` нет.
- `js/сеть.js`: `Сеть.встатьВОчередь`, `Сеть.отменитьПодбор`; вход в
  комнату — через существующую `начатьЖизньВКомнате`.
- `js/подбор-экран.js` — новый маленький экран «Ищем соперника» (счётчик,
  «Отменить»), по образцу `js/открытые-столы.js`.
- `js/дурак-путь.js`: включить режим `онлайн`, завести на подбор вместо
  отказа.

## Риски (обязателен reviewer)

- Правка `комнаты.js` — самый рискованный общий файл (270 КБ), ошибка
  роняет все идущие партии при перезапуске. Обязательна проверка
  `node -e "require('./комнаты.js')"` из `server/` до сдачи Э2, и reviewer
  **на Э2 тоже**, не только на Э3 (штаб усиливает предложение developer —
  правило CLAUDE.md зовёт ревьюера на любое рисковое место, а не только
  на сетевой протокол).
- Утечка памяти в очереди без уборки/потолка.
- Гонка «свели и в тот же миг отменил» — состояние записи меняется ровно
  в одном месте.
- Подсадка бота не должна включать «компанию» и не должна стать обходом
  суточного потолка очков от ботов (`ПОТОЛОК_ОТ_БОТОВ_В_СУТКИ`,
  `server/рейтинг.js`) — проверить, не менять этот файл.
- Боевой сервер комнат — порт 8790, не перезапускать. Тестовые копии —
  другой порт, `--без-памяти`, гасить по PID.

## Этапы (сдавать по одному, один файл — один исполнитель)

1. **Э1** — `server/подбор.js` + `tests/подбор-очередь.js`. Очередь и
   сведение в чистом node, без HTTP. developer.
2. **Э2** — `server/комнаты.js`: только `посадитьБотаОтПодбора` + экспорт.
   Прогон существующих серверных проверок дурака. developer → **reviewer**.
3. **Э3** — `server/сервер.js`: три двери + `tests/подбор-сервер.js` (двое
   фейковых клиентов + ломающий запуск `--сломать`). developer → **reviewer**.
4. **Э4** — `js/сеть.js` + `js/подбор-экран.js` + `js/дурак-путь.js`
   (включить режим). developer → tester (снимок экрана ожидания смотрителю).

**Открытый вопрос к Э4 (найден ревьюером на приёмке Э3, решение штаба
отложено сознательно).** Стол-подбор всегда не «компания» — клиент узнаёт
«это компания» по наличию `вид.застолом` (js/game.js:11685), и как только
оно появится, включится чужой рендер (список игроков по кругу). Поэтому
признак «соперник — бот» (обёртка.места/вид.застолом, где лежит
`этоБот`) до игрока сегодня физически не доходит на столе-подбора —
единственный путь его передать не сломав рендер, добавить отдельное
скалярное поле мимо списка мест. Пока не решено, нужно ли вообще
показывать игроку, что подсажен бот (мог обесценить ожидание), или
молчать, как молчала обычная локальная игра с ботом раньше. Решать при
разработке `js/подбор-экран.js`, не раньше.

Тестовые сценарии Э1/Э3 (шесть штук из описи developer): двое с одинаковыми
правилами сведены в одну комнату; одиночка с подкрученным порогом ожидания
получает бота, `этоБот: true`; подкидной и переводной не сводятся друг с
другом; отмена убирает из очереди; чужим `ключОжидания` чужой пропуск не
забрать; двойное «встать» не даёт двух мест в очереди. Ломающий запуск
обязан покраснеть на всех шести.
