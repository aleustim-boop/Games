# План: итог партии письмом от бота («история в бот»)

Опись и план — 2026-10-02 18:35 (время из `date`). Решение владельца 02.10 18:14: «Бот пишет итог после каждой партии».
В первую версию — только сетевые партии (их видит сервер комнат). Партии с ботом в браузере (билеты) — нет.

---

## 1. Опись: что уже есть

### 1.1. Конец сетевой партии — одна точка для всех игр

- **`server/комнаты.js:3029` — `учестьИтогПартии(комната)`**. Это единственная дверь: из неё вызывается и статистика (3034),
  и рейтинг (3051, `рейтинг.учестьПартию(комната.игра, застольеДляРейтинга(комната), ключПартии)`).
  Защита от повтора — пометка `комната.партияУчтена` (3031): сколько бы раз её ни звали, тело выполняется один раз на партию.
- Её зовут из 8 мест (обычный конец через `осмотретьПартию` 2999→3011, уборка 5709, откат входа 1886, возврат в прихожую 5473,
  досрочный конец 6247/6255 и т. д.), но все они сходятся сюда. Игры из `server/игры/*` (дурак, шашки, нарды, шахматы, деберц,
  домино, морской бой, катан, монополия, покер, захват) своего пути к рейтингу **не имеют** — проверено поиском: в `server/игры/*`
  `учестьПартию` не вызывается ни разу.
- Рейтинг считает партию, только если она доиграна (условие на 3046: по правилам / ничья / победитель при согласии). Брошенная
  партия рейтинга не трогает — и письма о ней не будет (это правильно).

Что в этой точке уже известно:

| Что | Где |
|---|---|
| игра | `комната.игра` (слово из `server/названия.js`, оттуда же склонения: `словаИгры(игра).вИгре` и т. п.) |
| кто сидел, их Telegram-номера | `застольеДляРейтинга(комната)` (3077–3141): `{ номер, имя, этоБот, напарник, уровень, победил, ничья, внеСчёта }`; номер = `игрок.телеграм` |
| исход каждого | там же: `победил` / `ничья` / иначе поражение; `внеСчёта` — партия закончена по согласию, а он не сдавался |
| +N к рейтингу | **возвращает** `рейтинг.учестьПартию` (`server/рейтинг.js:950–1091`): объект `{ номер: очков }` уже с учётом суточных потолков, напарника, одного человека с двух устройств и повторной доставки (повтор → `{}`). Сейчас комнаты этот ответ **выбрасывают** (комментарий в рейтинг.js:940 «Комнаты ответ не читают») |
| место (1-й, 2-й…) | **нет**. Общей таблицы мест нет ни у одной игры: только «победил/проиграл/ничья» (у дурака — `партия.проигравшие`). В первой версии пишем исход, не место |

Важно: `добавлено` содержит ключ только у тех, кого рейтинг реально учёл (человек с номером, не бот, не «вне счёта»).
Это готовый список адресатов: письмо уходит ровно тем, у кого есть строка в `добавлено`. Повторная доставка даёт `{}` — лишних писем не будет.

### 1.2. Telegram-номер игрока — надёжный

- Номер берётся **только из проверенной подписи initData**: `server/сервер.js:626 отметитьКтоЭто` перезаписывает поле
  `телеграм` результатом `ктоПрислал(initData)` (1360) → `ктоПодписал` (1372–1412: HMAC по ключу бота, сравнение за одинаковое время,
  подпись не старше суток). Присланный клиентом номер затирается всегда.
- Дальше номер ложится в `новыйИгрок(...).телеграм` (`server/комнаты.js:601`) и наружу не уходит (вид игрока собирается вручную).
- Игрок не из Telegram или без ключа на сервере — `телеграм: null`, такому письма нет.
- Имя из подписи (не то, что человек набрал в игре) сервер уже помнит: `имяИзПодписиПоНомеру` (`server/сервер.js:601–617`), его же
  использует лента бота, чтобы в письме нельзя было назваться «Поддержкой Telegram».

### 1.3. Как сервер ходит в Telegram — уже умеет

- `server/сервер.js:129` — встроенный `https` Node. `спроситьTelegram(метод, тело)` (1419) → `запросВTelegram` (1427–1462):
  POST на api.telegram.org, ожидание 5 с, все беды молчаливые (в тексте ошибки мог бы оказаться адрес с ключом).
- Подмена для проверок уже есть: `оснасткаДляПроверки(токен, труба)` (1281) — выдуманный ключ + поддельная «труба» вместо Telegram.
- Уже шлются письма: зов знакомого (`/позвать`, 2750–2860, с 403 → `неЗвать.запретить(…, 'ботНеПишет')` на 2858) и **лента бота**
  (`server/лента.js`, подключена в `server/сервер.js:2990–3017` через `комнаты.слушатьСобытия`). Новых библиотек не нужно.

### 1.4. Ключ бота на ВМ — уже есть

- Сервер читает ключ не из переменной окружения, а из файла **`bot/.env` рядом с собой** (`server/сервер.js:223 прочитатьНастройки`,
  1225 `ТОКЕН_БОТА = …BOT_TOKEN`). На ВМ это `/srv/games/bot/.env`; его кладёт `штаб/вм-env.js` (строки 32, 136: `BOT_TOKEN`,
  `GAME_URL`, `GAME_SERVER_ORIGIN`), там же бот. Переносили 23.09 (штаб/важное.json, «токен-бота-в-истории-хаба-30-09»).
- **Проверено 02.10 18:3x**: `POST https://igra.medart.com.ua/приглашение` с пустым телом ответил `{"умеем":true,"ок":false}` —
  у боевого сервера ключ бота **есть** (ответ — только «да/нет», сам ключ нигде не показывается).
- Служба на ВМ — `games-server` (systemd); юнит-файла в репозитории нет, переменных окружения сервер, кроме `OPEN_HIDDEN_GAMES`
  (`server/игры/реестр.js:111`) и папки данных (`server/папка-данных.js:56`), не читает.
- **Вывод: от владельца ключ не нужен.** Вводить отдельную переменную окружения не предлагаю: это второй путь к тому же секрету,
  который разойдётся с первым. Модуль берёт ключ тем же путём, что лента (через `спроситьTelegram`).

### 1.5. Отказ игрока от писем — есть, но один на всё

- `server/не-звать.js`: `запретить(номер, 'сам' | 'ботНеПишет')`, `почемуНеЗвать(номер)`; `'сам'` — навсегда, `'ботНеПишет'` (403) —
  на сутки. Хранит **одну** причину на номер (Map номер → {причина}).
- Кнопка в письме несёт слово `'не-звать'`; нажатие ловит `bot/бот.js:365–390` и шлёт серверу `/не-звать` (`server/сервер.js:2874`).
  Ответ бота человеку сейчас: «приглашений от игры вам больше не придёт».
- Лента уже переиспользует эту память (`server/сервер.js:3012–3013`).

### 1.6. Ссылка «Играть ещё»

- Сервер знает адрес сайта: `ЗАПАСНОЙ_АДРЕС` из `GAME_SERVER_ORIGIN` (`server/сервер.js:399`), на ВМ это `https://igra.medart.com.ua`;
  страница игры — `названия.словаИгры(игра).страница`.
- Кнопка `{ text: 'Играть ещё', web_app: { url } }` в личном чате с ботом открывает мини-приложение сразу (с initData).
  Нет адреса — запасная кнопка-ссылка `https://t.me/<бот>?start=invite_<метка>` (тот же путь, что `сообщениеВПриложение`, 1717–1743:
  бот отвечает кнопкой «Играть»). Нет и имени бота — письмо без кнопки «Играть ещё».

## 2. Как будет устроено

```
комнаты.учестьИтогПартии ── добавлено = рейтинг.учестьПартию(...)  (ответ больше не выбрасываем)
        └─ объявитьИтог(комната, застолье, добавлено) → слушатели событий, что: 'итог'
               (лента такое событие молча пропускает: её текстПисьма → null)
сервер.js: комнаты.слушатьСобытия(...) → итогВБот.событие(данные)   [имена — из подписи]
server/итог-в-бот.js: собрать письма → очередь → спроситьTelegram('sendMessage') с паузой
```

### Модуль `server/итог-в-бот.js` (новый, «чистый», как лента)

- Сети, файлов и Telegram сам не знает. `подключить({ отправить, почемуНеЗвать, запретить, имяПоНомеру, адресИгры, имяБота, сейчас, отложить })`.
  Пока `отправить` не задан — модуль выключен, `событие()` ничего не делает.
- `событие({ что:'итог', игра, места:[{ номер, этоБот, имя, исход, очков, напарник }] })`: для каждого места с номером и строкой
  в `добавлено` собирает письмо и ставит в очередь.
- **Очередь**: одно письмо за раз, пауза 100 мс между письмами (≤10 в секунду при лимите Telegram ~30/с на бота и 1/с на чат —
  а адресаты в одной партии разные). Потолок очереди — 500 писем: сверх — выбрасываем самые старые и пишем одну строку в журнал.
- **Ответ 429** (слишком часто): ждём `parameters.retry_after` секунд (не больше 60) и пробуем это письмо ещё один раз; второй 429 — бросаем письмо.
- **Ответ 403** (игрок не запускал бота / заблокировал) — молча, и `запретить(номер, 'ботНеПишет')` на сутки, как лента и зов.
- **Отказ «сам»** (`почемуНеЗвать === 'сам'`) — не пишем. `'ботНеПишет'` — тоже не пишем (сутки).
- Сбой сети, `null` ответ — молча, ничего не повторяем. Тексты ошибок Telegram в журнал не пишем (в них может быть адрес с ключом).
- Антиспам: не больше 30 итогов одному человеку в час (дальше молча пропускаем) — страховка от ботов-фермеров, а не ограничение для живых.

### Тексты (простые, без глаголов прошедшего времени при имени — правило ленты, `server/лента.js:63–68`)

Имена соперников — из подписи Telegram (`имяИзПодписиПоНомеру`), у бота — «бот», у гостя без подписи — «игрок».
Напарник в «2 на 2» — отдельной строкой. Больше 3 соперников — «Лена, Петя и ещё 2».

Шашки, победа:
```
Шашки — победа!
Соперник: Мария
Рейтинг: +10 очков
[Играть ещё]  [Не присылать итоги]
```
Дурак вчетвером, проигрыш:
```
Подкидной дурак — вы остались в дураках.
За столом: Лена, Петя и бот
Рейтинг: без изменений
[Играть ещё]  [Не присылать итоги]
```
Шахматы, ничья:
```
Шахматы — ничья.
Соперник: Олег
Рейтинг: +5 очков
[Играть ещё]  [Не присылать итоги]
```
Правила строки «Рейтинг»: `> 0` → «+N очков» (склонение очко/очка/очков), `0` → «без изменений» (не объясняем почему: потолок, бот, напарник).
У дурака поражение — «вы остались в дураках», победа — «вы не в дураках»; у остальных игр — «победа» / «поражение» / «ничья».
Поле `названия.словаИгры(игра).название` — заголовок; у дурака — «Подкидной дурак».

## 3. Этапы (каждый — 1–2 файла, проверка на node без сети)

**Э1. Модуль `server/итог-в-бот.js` + `tests/итог-в-бот.js`.** Разработчик, лёгкая модель.
- Текст писем, кнопки, очередь с паузой, 403/429, отказы, потолок в час, «выключен без отправить».
- Проверка: подменённые `отправить` (журнал), `сейчас`/`отложить` (без настоящих секунд). Сверяет: текст трёх примеров выше
  слово в слово; 403 → `запретить(номер,'ботНеПишет')` и больше этому номеру писем нет; 429 с `retry_after:2` → повтор через 2000 мс
  ровно один раз; `'сам'` → письма нет; бот и человек без номера → письма нет; 6 писем → 6 вызовов с паузами ≥100 мс; без `подключить` — ноль вызовов.
  «Ноль писем» в позитивных случаях = провал.
- Ломающий запуск: `node tests/итог-в-бот.js --модуль <путь к копии>` — исполнитель кладёт копию модуля во временную папку
  и портит в ней обработку 403 (не зовёт `запретить`) и паузу (0 мс) → проверка обязана покраснеть на обоих.

**Э2. Событие «итог» в `server/комнаты.js` + `tests/итог-событие-комнат.js`.** Разработчик, **полная** модель (общий файл 6,5 тыс. строк) + ревьюер.
- В `учестьИтогПартии` (3051) сохранить ответ `рейтинг.учестьПартию` и позвать новую `объявитьИтог(комната, застолье, добавлено)` —
  тем же списком `слушателиСобытий`, `что: 'итог'`, `игра`, `код`, `места[]` (номер, имя игрока в игре, этоБот, уровень, исход, очков,
  напарник). Сбой слушателя партию не ломает (как `объявитьСобытие`, 559–565).
- Проверка (по образцу `tests/лента-события-комнат.js`, модулем, без порта, с `сберечь-данные.js`): стол шашек на двоих с номерами →
  сдача одного → ровно одно событие «итог», у победителя `очков>0`, у проигравшего исход «поражение»; повторный `учестьИтогПартии`
  (возврат в прихожую) → событий не прибавилось; брошенная партия → событий 0; гость без номера и бот — в `места` есть, но без `очков`;
  в виде игроку (`видДляИгрока`) нет новых полей.
- Ломающий запуск: флаг `--сломать` в самой проверке (слушатель теряет событие) и `--сломать-повтор` (проверка зовёт итог дважды,
  сняв пометку `партияУчтена` у своей комнаты) — обе обязаны покраснеть. Файл проекта не портится.

**Э3. Провода в `server/сервер.js` + `tests/итог-в-бот-сервер.js`.** Разработчик, полная модель + ревьюер (сервер, сеть).
- `итогВБот.подключить({ отправить: письмо → спроситьTelegram('sendMessage', …), почемуНеЗвать, запретить, имяПоНомеру: имяИзПодписиПоНомеру.get,
  адресИгры: ЗАПАСНОЙ_АДРЕС, имяБота: имяБотаБезОжидания })` только если `умеемГотовитьПриглашения()`; иначе не подключать.
  `комнаты.слушатьСобытия(данные => данные.что === 'итог' && итогВБот.событие(данные))`.
- Одна строка в журнал при старте: «Итоги партий в бот: включены» или «… выключены — у сервера нет ключа бота». Ключ не печатается.
- Проверка по образцу `tests/лента-бота-сервер.js`: `оснасткаДляПроверки('1:выдуманный', труба)` → сыграть сетевую партию
  через двери сервера на свободном порту с `--без-памяти` → в трубе ровно по одному `sendMessage` каждому человеку, `chat_id` = номер
  из подписи, кнопка `web_app.url` начинается с адреса игры; без ключа (оснастка не ставилась, `bot/.env` проверки не читает) — в трубе ноль,
  в журнале строка «выключены».
- Ломающий запуск: флаг `--сломать` в самой проверке — её слушатель подключается без фильтра `что === 'итог'` и шлёт письма
  и на события ленты; сверка «ровно по одному письму на человека за партию» обязана покраснеть. Файл проекта не портится.

**Э4. Кнопка «Не присылать итоги».** Зависит от решения штаба (см. §5, вопрос 1).
- Вариант А (рекомендую для первой версии): одно общее «молчание бота». Кнопка шлёт то же слово `'не-звать'`, память та же (`'сам'`).
  Правка — только `bot/бот.js` (текст ответа «Готово: писем от игры вам больше не придёт…») и, при нужде, текст кнопки в ленте.
  Проверка: `bot/проверка-*.js`-образец — подменённый `вызовAPI`, нажатие → запрос `/не-звать` и новый текст. Ломающий — копия бота со старым текстом.
  После — штаб перезапускает бота на ВМ.
- Вариант Б: отдельный отказ только от итогов. `server/не-звать.js` хранит одну причину на номер — новая причина затёрла бы «сам»;
  нужна вторая память (или список причин) + новое слово кнопки в `bot/бот.js` + дверь в `server/сервер.js`. Это 3 файла, два этапа.

**Э5. Выпуск.** Штаб: коммит → перезапуск боевого сервера `node штаб/перезапуск-сервера.js`, **посмотрев, что живых комнат ноль**
(комнаты живут в памяти) → владелец играет одну сетевую партию с телефона и смотрит письмо в чате бота.

Итого: 3 этапа кода обязательно (Э1–Э3) + Э4 (1 файл при варианте А) + выпуск.

## 5. Вопросы штабу / владельцу

1. **Отказ**: А — одна кнопка «Не присылать итоги» = бот замолкает целиком (и зовы тоже); Б — отдельно только итоги (+2 файла).
