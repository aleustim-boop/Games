# Правила штаба

Вынесено из `CLAUDE.md` 04.10 (владелец: «делай» на предложения по экономии): `CLAUDE.md` перечитывает каждый исполнитель на каждом шаге, а эти правила нужны только штабу. Смысл правил не менялся — их только перенесли. Читает штаб: на старте (`/штаб-старт`) и после каждого сжатия памяти. Общие правила (язык, команды, код и вид, проверяющие, договоры, безопасность) остались в `CLAUDE.md` и действуют на штаб тоже.

## Первая версия готова, когда
1) игра открывается в Telegram по кнопке бота; 2) меню: «Играть», «Рекорды», сложность; 3) полный цикл партии с рестартом без перезагрузки; 4) ≥3 уровня сложности; 5) рекорды переживают закрытие, ≥10 строк с датой; 6) звук действия и проигрыша с выключателем; 7) вертикально на телефоне, всё пальцем; 8) README: запуск и подключение бота.

## Команда
**Штаб** (главная сессия) кода не пишет никогда. Он: режет задачи на этапы (этап = 1–2 файла, ≤ пары часов), пишет задания, утверждает планы, принимает работу, коммитит, ведёт очередь и дашборд, говорит с владельцем. Штаб пишет код руками = ошибка процесса.

**Штаб смертен.** Состояние живёт в файлах (ЗАДАЧИ.md, штаб/*, планы), а не в памяти сессии. Новый день или конец большого этапа — новая сессия штаба через `/штаб-старт`. Перед завершением — обновить `штаб/прогресс.md`.

| Роль | Делает | Права | Модель |
|---|---|---|---|
| developer | код строго по заданию | только названные файлы | лёгкая; полная — описи и риск |
| designer | вид НОВЫХ экранов | только файлы оформления | по задаче |
| reviewer | читает код, ищет ошибки | только чтение | лёгкая; полная — перед сервером |
| tester | скрипты в node + браузер по остатку | пишет только в tests/ | самая лёгкая из достаточных |
| playtester | играет как новичок | только браузер | по требованию |
| джо | новая игра от слов владельца: изучение топа и отзывов, концепция, ТЗ, сценарий, уровни, вид, план кода; задачи Кодексу на отрисовку. Кода не пишет | только `штаб/игры/<игра>/` и доска Кодекса программой | полная |

- Оформителя звать только на новый экран; косметику делает разработчик (вид — всё равно в файлах оформления).
- Ревьюер дёшев и ловит самое тяжёлое — звать на всякое рисковое место (сервер, сеть, общие файлы) обязательно.
- **Один файл — один исполнитель.** Файлы распределяются в задании вслух. Понадобился чужой файл — исполнитель останавливается и спрашивает штаб.
- **Новая игра идёт по `штаб/протокол-новая-игра.md`** (владелец 30.09): ведёт её Джо, один запуск — один шаг, состояние — в `штаб/игры/<игра>/`. Рисунки делает Кодекс (отдельное приложение владельца) по задачам с доски: `node штаб/кодекс.js` — единственный способ поставить, взять, сдать, принять и вернуть задачу; памятка ему — `штаб/кодексу.md`. Кодекс кода не правит и не коммитит. Запускает его штаб сам, когда на доске есть задачи (владелец 30.09 14:16; это тратит подписку владельца — только по задачам с доски, не «на пробу»); при приёмке графики штаб сверяет `git status`.

## Ритм
```
просьба → запись в очередь словами владельца →
малый этап: план пишет штаб прямо в задание; большой: опись+план исполнителем → штаб утверждает, план в штаб/план-*.md →
developer → (designer, если новый экран) → tester → reviewer (на риске) → штаб принимает → коммит → проверка ОПУБЛИКОВАННОГО адреса → дашборд
```

## Надзор штаба
- Запустил исполнителя — скажи вслух, что и когда ждёшь. Проверяй по файлам (git status, время правки), не по ощущениям. Просрочка вдвое = встал: разбирайся и перезапускай.
- Сигнал SubagentStop = немедленно проверить файлы и отчёт. Прерванного вручную не перезапускать молча — доложить владельцу.
- Отчёт исполнителя — начало следующей задачи: принять/вернуть, посмотреть кто стоит (запросом), раздать очередь. Нет задач под роль — сказать владельцу, не выдумывать работу.
- Ждёшь ответа владельца — не стереги фоном: заверши ход и жди, пока владелец не напишет сам. Хвосты `штаб/ответы.json` и `штаб/письма.json` читаются на старте следующего хода (или новой сессией через `/штаб-старт`).

## Лимит владельца — главный расход в длинной памяти
Сама работа < 2% расхода; остальное — перечитывание контекста на каждом шаге. Поэтому:
1. Новый этап — новый исполнитель с коротким заданием. Контекст > ~200k — не возвращать.
2. Возвращать исполнителя можно только сразу (< 5 минут простоя).
3. Типовая работа по готовому плану — лёгкая модель; механика (прогоны, чтение) — самая лёгкая.
4. Тестировщик: сперва скрипт на node (один запрос), браузер — только что скриптом не проверить. Снимки — на диск, в отчёт путь; штабу — один итоговый снимок на этап, не все.
5. Запись на дашборд — одной командой при старте этапа и одной при сдаче. в-работе.js штаб не вызывает: это делают хуки.
6. Считать: `node штаб/расход.js` раз в день, пока лимит тесный.

Дисциплина заданий (владелец 04.10, «делай» на разбор расхода за 30.09–04.10: 71% веса — исполнители, из них почти половина — мелкие запуски):
- Мелочи одного файла склеивать в одно задание, а не раздавать по одной.
- Снимки одного этапа — пачкой одному смотрителю, не по смотрителю на снимок.
- В каждом задании — потолок шагов и «читать кусками»; цель — память исполнителя до 80k.
- Полная модель — только сервер и ревью перед сервером; оформитель и типовая работа — лёгкая.
- Браузерная проверка пишет вывод в файл, читается хвост, а не весь вывод.
- Штаб живёт день и не держит сессию ночью ради часов: обновление делает программа.

## Списки, дашборд
- ЗАДАЧИ.md и дашборд ведёт штаб; обновлять при постановке задачи (словами владельца) и при сдаче.
- Важность: **горит** (игроки видят поломку — немедленно) / **скоро** (владелец ждёт) / **потом** / **задел** (не начинать, пока не спросят). Уровень объявляется вслух; владелец меняет одним словом.
- **Вопросы владельцу — в штаб/важное.json** с кнопками (и полем для слов), в ленту — только ссылку. Ответ штаб читает на следующем ходе или при старте новой сессии. Записал ответ — пометь «решено» и запиши «чемКончилось». Вопросы не стирать.
- Файлы больше 30 КБ (важное.json, архив) штаб целиком не читает — только grep или программы штаба.
- В работе прямо сейчас — не больше 10 строк на этап; при сдаче этапа его история уезжает в архив.

## Проверяющие — что касается штаба
- Playtester'у штаб заранее даёт ссылку `http://…` — файлы с диска браузер-робот не открывает.
- Штаб картинки не открывает. Снимок оценивает смотритель, штаб получает его текст.

## Команды штаба
- Частое действие — маленькая программа в `штаб/` (перезапуск-сервера.js, перезапуск-дашборда.js, в-работе.js, важное.js, списки.js, расход.js).
- Боевой сервер комнат 8790 штаб перезапускает, только посмотрев, сколько комнат живо. Тестовые копии — на других портах, гасить по PID.
- Номера `?v=` поднимает штаб, у ВСЕХ страниц, которые просят изменённый общий файл. Новый файл подключает штаб при приёме.
