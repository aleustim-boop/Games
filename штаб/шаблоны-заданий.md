# Шаблоны заданий исполнителям

Задание должно умещаться примерно в 300 токенов: что сделать, где, что уже решено, что считается результатом. Всё остальное исполнитель прочтёт сам из файлов. Не пересказывать историю проекта и не вставлять куски CLAUDE.md — он загружается исполнителю сам.

## Перед каждым запуском (владелец 04.10, «делай… все» на разбор расхода)
1. **Склеить.** Есть ещё мелочи в тех же файлах — в это же задание. Один запуск на одну строчку правки — запрещён.
2. **Модель.** sonnet — типовое; haiku — прогоны и чтение; opus — только сервер и ревью перед сервером. Оформитель — sonnet.
3. **Потолок шагов и чтение кусками** — в каждом задании строкой: «Не больше N шагов; большие файлы — Grep и Read куском». Цель — память исполнителя до 80k.
4. **Где искать.** Назвать функцию или строку (`js/game.js` ~:5367), чтобы исполнитель не читал файл в поисках.
5. **Снимки одного этапа — одному смотрителю пачкой.**
6. **Браузерная проверка** — вывод в файл, в отчёт хвост. Node-проверки штаб гоняет сам, без исполнителя.
7. **Возврат** — только сразу и только если память исполнителя меньше 100k; иначе новый исполнитель с коротким заданием.

## developer

```
Задача: <одно предложение, что должно заработать>.
Файлы: <точный список; чужие файлы не трогать, новый файл подключает штаб>.
Где: <функция или строка в файле>. Не больше <N> шагов; большие файлы — Grep и Read куском.
Уже решено: <2–4 строки принятых решений, чтобы не перепридумывал>.
План: <шаги, если задача маленькая — штаб пишет план сам, без круга утверждения>.
Готово, когда: <проверяемый признак + какой скрипт из tests/ должен пройти>.
В отчёте: что сделал, как проверить руками, какие строки подключения нужны от штаба.
```

## tester

```
Задача: проверить <что именно> после правки <чего>.
Файлы: tests/<какие именно>; чужие файлы не трогать.
Сперва скриптом на Node (tests/…), браузер — только для <что скрипт не видит>.
Не больше 40 шагов. Ломающий запуск обязателен: проверка должна уметь краснеть.
Готово, когда: отчёт по форме, снимки на диске путями, «Итого проверок: N, провалов: M».
```

## reviewer

```
Задача: проверить <файлы> на <главный риск этой правки: утечка карт, расход, гонки…>.
Файлы: <точный список файлов на чтение>.
Что менялось и зачем: <2–3 строки>.
Ответ: нумерованный список замечаний с путём и строкой, или «замечаний нет».
```

## designer

```
Задача: <экран/элемент> по образцу <файл в эталон/>. Только новый экран, не косметика.
Файлы: style*.css <какие именно>; разметку не менять, о недостающем классе — сказать штабу.
Единый стиль: ширина, лист «⋯», нижняя полоса — общие; вид материалов — не плоский.
Снимки — готовым скриптом из tests/ на диск, штабу нужно не больше двух за задание.
Готово, когда: снимок 390×844 на диске, путь в отчёте.
```

## смотритель

```
Задача: оцени снимки этапа пачкой: <пути ко всем снимкам этапа>.
Вопросы по каждому: что на экране; совпадает ли с ожиданием <описание ожидания> (да/нет); что не так.
Ответ: до 4 строк на снимок, в конце «Итог: принято N из M».
```
