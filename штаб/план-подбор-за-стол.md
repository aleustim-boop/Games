# План: «Открыть подбор игроков» — сервер сажает за стол того, кто ищет игру

Слово владельца (25.09 10:46): «Сделать функцию по-настоящему. Переключатель открывает стол для подбора, и сервер сажает к вам того, кто ищет игру».

## 1. Опись: что уже есть

## 2. Решение

**Смысл переключателя** = `комната.открытый`: включён — стол виден в списке «Открытые столы» **и** к нему сажает «Найти игру». Выключен — стол только по коду. Второго признака не заводим: список и подбор — одна и та же «открытость», иначе хозяин путался бы в двух переключателях.

**Посадка искателя (сервер).** Новая функция в комнаты.js `усадитьИскателя(игра, правила, человек)` — одним синхронным вызовом: ищет подходящий стол и сажает через `войтиВКомнату`. Между поиском и посадкой нет `await` — Node однопоточный, поэтому «два искателя на одно место» невозможно: второй просто не найдёт свободного места и пойдёт дальше (в очередь / к следующему столу).

Подходящий стол:
- `столВиденВСписке` (открыт, ожидание, есть место, есть люди) — готовая проверка;
- та же игра;
- хозяин **на связи прямо сейчас** (`наСвязи`), строже, чем для списка: список человек видит сам, а в подборе его сажают вслепую — к погасшему телефону сажать нельзя;
- за столом нет самого искателя (тот же номер Telegram) — не сажаем к себе же;
- дурак: совпадает «переводной»; стол не «парами»; число мест — см. вопрос 1 (по умолчанию только стол на двоих, как и сам подбор 1×1). Шашки/нарды: правил нет, совпадает только игра.
- Несколько подходящих — первым тот, кто **раньше открылся** (`открытаС`), тот же порядок, что в списке: кто дольше ждёт, тому и соперник.

**Когда подбор смотрит открытые столы:**
1. `/подбор` — **до** постановки в очередь: есть стол → сразу ответ `{ статус:'свели', код, пропуск }` (клиент это уже умеет). Открытый стол важнее другого искателя в очереди: хозяин ждёт дольше и уже сидит.
2. `/подбор-новости`, каждый шаг со статусом «ждёт» — стол мог открыться, пока человек ждёт. Посадили → `подбор.отменить(ключ)` и забыть личность (запись в очереди снимается тем же синхронным ходом, партнёр по очереди её уже не получит).
3. `пора_бота` (20 с) — перед ботом ещё раз стол; нет стола — бот, как сейчас.
Статус «свели» из очереди важнее стола (пару уже пообещали двоим).

**Выключение / заполнение / уход хозяина** — отдельной работы не требуют: выключил → `открытый=false`; стол полон, партия началась, хозяин ушёл или молчит → `столВиденВСписке`/`наСвязи` дают «нет». Хозяин вышел совсем — звание переходит (существующая логика), новый хозяин видит переключатель в прежнем положении.

**Потерянный ответ и обрыв.** В `/подбор` — `следитьЗаОбрывом` и `отменитьВход`, как у `/сесть`. Плюс короткая память «кого подбор посадил» (номер Telegram → код+пропуск, 60 с, как `парыПодбора`): повторный `/подбор` того же человека получает то же место, а не второе. В `/подбор-новости` перед посадкой проверять флаг `завершено` (опрос уже оборвался — не сажаем).

**Метку вкладки в `войтиВКомнату` из подбора не передаём** (как пара подбора сейчас): метка возвращает чужой пропуск при совпадении, а в подборе искатель не знает стола — пусть не будет даже теоретической дорожки. Повтор решает память выше.

**Что увидит хозяин.** Ничего нового не рисуем: в компании (дурак) уже есть событие «вошёл» с именем и письмо «3б» «стол собран — жмите «Начать»»; у шашек/нард партия начинается сама, строка связи «Соперник пришёл — играем!». Предлагаю (не в этом объёме): отдельные слова «К вам подсел игрок из подбора: Имя» — это новое событие в партия-по-сети.js.

**Искатель** попадает за стол тем же путём `начатьЖизньВКомнате`: у дурака — экран комнаты гостем («ждём, когда хозяин начнёт»), у шашек/нард — сразу партия.

**Переключатель (клиент, js/дурак-комната.js).** Модель `подбор`: `видна` (только для игр из списка подбора, сейчас дурак), `включён = вид.открытыйСтол === true`, `доступен` — хозяин, этап «ожидание», нет запроса в пути. Не хозяину — видно положение, но нажать нельзя, подсказка «Подбор включает хозяин стола». Нажатие → `двери.действие('открыть-стол', { открыть: !включён })` через готовый `запуститьДействие` (защита от двойного нажатия и показ отказа уже есть). `aria-checked` — по правде, надпись «скоро» прячется классом `скрыт`. Вид — только классы, стили уже есть.

## 3. Для каких игр сейчас
- **Дурак** — полностью: переключатель + посадка.
- **Шашки и нарды** — только сервер: их столы из «Создать игру» уже открыты, и «Найти игру» начнёт сажать к ним. Переключателя у них нет (свои экраны) — его не добавляем в этом объёме.
- **Деберц, домино, катан, монополия** — подбора на сервере нет. Предложение: строку на их экранах **прятать** (из js/дурак-комната.js классом `скрыт`, файлы страниц не трогаем) — «скоро» без плана = мёртвая кнопка. Вопрос 3.

## 4. Безопасность
- Искатель узнаёт код только **после** посадки — как у `/сесть`. В отказе и в «ждёт» ни кода, ни числа столов, ни имён.
- Закрытый стол (`открытый !== true`) не находится никогда: условие берём из `столВиденВСписке`, отдельного «почти такого же» не пишем.
- Правила искателя — только из тела `/подбор` после той же чистки, что сейчас (`играПодбораИзТела`, «переводной» только у дурака); личность — только из подписи Telegram.
- Новых полей наружу не добавляем. `открытыйСтол` уже идёт в вид; если когда-нибудь понадобится новое — только через `видДляИгрока` (server/партия-по-сети.js) и видДляИгрока нужной игры.
- Лимит «2 открытых стола на человека» остаётся — список и подбор не забьёт скрипт.
- Ревьюер обязательно: гонка «пара из очереди / стол» в одном шаге опроса, отмена записи очереди, обрыв на посадке, повтор `/подбор`.

## 6. Вопросы владельцу (в штаб/важное.json)
1. **За какие столы сажать «Найти игру»?** а) только за стол на двоих (по умолчанию — «Найти игру» обещает игру один на один); б) за любой стол дурака с тем же «переводным», где есть место (3–6 игроков, без «парами»).
2. **Стол дурака заполнился гостем из подбора — начинать сразу?** а) нет, хозяин жмёт «Начать», как сейчас при посадке из списка (по умолчанию); б) да, на двоих партия стартует сама.
3. **Что со строкой в деберце, домино, катане, монополии, где подбора нет?** а) спрятать (по умолчанию); б) оставить «скоро».
